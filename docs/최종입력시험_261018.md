## 2. 1단계 — 화면 수정

### 2-1. 드롭다운이 열린 채 휠
- **원인**(하네스로 재현 · 1280×760 · 화면 중간까지 내린 상태)
  1. 목록창(Popup)은 별도 창이지만 휠은 논리 트리를 따라 바깥 `BodyScroll` 까지 올라간다. C-3 `NestedWheelScroll` 이 "안쪽 끝이면 바깥을 굴린다"를 목록창 안의 휠에도 적용 → 빠른추가 종명(253개) 목록 끝에서 휠 → 바깥 393 → 441, 목록창은 제자리(칸에서 떨어짐).
  2. Telerik `RadComboBox.IsMouseWheelEnabled`(기본 True) — **포커스가 있는 닫힌 콤보 위의 휠이 값을 바꿨다**(서식수변 점수 `·` → 30). 화면을 굴리려다 점수가 조용히 바뀐다.
- **고친 것** — `Behaviors\DropDownWheelGuard.cs`(새 파일 · `App` 생성자에서 등록 · 앱의 모든 창)
  - 목록이 열렸고 휠이 목록창 **안**이면 목록만 움직이고 바깥으로 넘기지 않는다(목록 끝에 닿아도).
  - 목록창 **밖**이면 목록을 닫는다(그 휠 한 칸은 소비).
  - 닫힌 `RadComboBox` 는 `IsMouseWheelEnabled=False` + 콤보 위 휠은 가장 가까운 스크롤을 대신 굴린다(값은 안 바뀌고 화면은 내려간다).
  - `NestedWheelScroll` — 바깥까지 시각 트리로 이어지지 않는 휠(목록창에서 온 것)은 손대지 않는다.
  - 대상: `RadComboBox`(SingleChoiceBox·MultiChoiceBox·지점·빠른추가·서식수변 점수·자료함 콤보) · `RadAutoCompleteBox`(그리드 국명) · `RadDatePicker` · WPF `ComboBox`·`DatePicker`.
- **하네스 `wheel_dropdown`(17항목)** — 서식수변 점수(짧은 목록) · 빠른추가(긴 목록 · 끝에서 3번 더) · 어류 하천형태/흐름상태(유속)/흐름상태(채집)/채집도구 · 저서 투명도 · 개황 지점(43개)·조사일 달력 · 그리드 국명 자동완성 · 자료함 창 콤보 · 닫힌 점수 콤보(값 그대로·화면 스크롤).
