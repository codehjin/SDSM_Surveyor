## 1. M8 비정상종 비율 — 정수 나눗셈 결함

**결정: 지침대로 실수 나눗셈으로 수정한다.**

실증: 비정상 199 / 총 200개체(99.5%)인데도 계산 결과가 **0%**, M8은 **만점 12.5**.
비정상 개체가 총개체수 이상일 때만 0이 아닌 값이 나오므로 **M8은 사실상 항상 만점**이다.

```csharp
// 현행 (결함) — 둘 다 int라 소수점이 절사된다
double abnormalRatio = abnormalCount != 0 ? (abnormalCount / totalIndiv) * 100 : 0;

// 수정 — 나눗셈 "앞"에서 실수로 승격 + 0 나누기 가드
double abnormalRatio = totalIndiv > 0 ? (double)abnormalCount / totalIndiv * 100.0 : 0;
```

> ⚠ `(double)(abnormalCount / totalIndiv)` 처럼 **나눈 뒤에 캐스팅하면 소용없다.** 이미 0이 된 값을 실수로 바꿀 뿐이다.

**부수 효과 — 0으로 나누기 해소**: 현행은 `abnormalCount > 0` 이고 `totalIndiv == 0` 이면 `DivideByZeroException`이 난다(양쪽 모두). 관리자는 **일괄입력이 통째로 실패**할 수 있다. 위 `totalIndiv > 0` 가드로 함께 해결된다.

- 조사자: `Ecology\EcologyCalculator.cs`
- 관리자: `GB.cs` (→ `ADMIN_TASKS.md` §6-1)

## 2. 어류 0종 처리 — E등급 부여

**결정: 조사를 수행했으나 0종이면 점수 0 · 등급 E(최하)로 한다.**

### 왜 현행이 문제인가
관리자 `GetFAI`에 0 가드가 없어 **0종이면 합계 37.5(D등급)** 이 된다.
내성종 0% · 잡식종 0% · 비정상종 0% 는 각각 "낮을수록 좋음"이라 **만점(12.5×3)** 을 받기 때문이다.
→ "어류가 한 마리도 없다"가 "내성종·잡식종이 없어 건강하다"로 계산되는 역설. **D는 명백한 과대평가다.**

### 처리 규칙 (우선순위 순)

| 상황 | 점수 | 등급 |
|---|---|---|
| 1. **조사불가 사유** 있음(접근불가·건천화·준설·공사중) | `null` | `"-"` |
| 2. **조사 수행 + 0종** (아래 §2-1로 선언) | `0` | **`E`** |
| 3. 종 목록 미입력(아직 입력 안 함) | `null` | `"-"` |

> 1번이 2번보다 우선한다. 조사 자체를 못 했으면 0종이 아니다.

### 2-1. "미입력"과 "0종"을 구분하는 방법 — 명시적 선언

`CLAUDE.md` §7.2의 **결측(null)과 0을 엄격히 구분** 원칙이 그대로 적용된다.
종 목록이 비어 있다는 사실만으로는 "아직 안 넣음"인지 "조사했는데 없음"인지 알 수 없다.

→ 각 화면에 **`출현종 없음(0종)` 체크**를 추가한다.
- 체크 시: 종 목록이 비어도 **조사 완료로 간주** → 점수 0 · 등급 E, 내보내기 활성화
- 미체크 + 종 목록 비어 있음: 현행대로 `-`(미입력)
- 조사불가 사유가 있으면 그것이 우선(`-`)

### 2-2. 내보내기 게이트 완화

현재 내보내기는 **유효 개체 1건 이상**에서만 활성화된다.
→ 조사는 했는데 0종인 지점(도심 복개하천 하류, 극심 오염 구간 등)의 **결과를 전달할 방법이 없다.**

**수정**: `출현종 없음(0종)` 이 선언되었거나 조사불가 사유가 있으면 **종이 없어도 내보내기 허용**.

### 2-3. 저서동물도 동일 원칙

`BenthosCalculator`도 0종이면 `null`을 반환한다. 어류와 같은 규칙을 적용한다.
- 조사불가 → `-`
- 조사 수행 + 0종 선언 → BMI 점수 0 · 등급 **E**
- 미입력 → `-`

> BMI 등급 하한은 `E`(0 이상)이므로 0점은 자연히 E가 된다.

### 2-4. 관리자 쪽

`GB.GetFAI`에 동일 규칙을 넣는다(0종이면 37.5가 아니라 0·E).
과거 데이터 재산출 여부는 `ADMIN_TASKS.md` §6-2와 함께 판단한다.

## 3. BMI 음수 점수 등급 — `Check`로 통일

오탁치 `s > 4` 인 종이 있으면 BMI 점수가 음수가 될 수 있다.
- 관리자: `"Check"` (검토 필요 표시)
- 조사자: `"E"`

**결정: 관리자 쪽(`Check`)을 채택한다.** 음수는 정상 범위를 벗어난 값이므로 등급을 매기기보다 **검토 대상으로 표시**하는 편이 옳다.

> 실제 종목록의 오탁치는 0~4라 정상 데이터에서는 발생하지 않는다. 낮은 우선순위.

### 고친 것

**① M8 실수 나눗셈** (`GB.cs` · `EcologyCalculator.cs`)
```csharp
double 비정상개체수비율 = 총개체수 > 0 ? (double)비정상개체수 / 총개체수 * 100.0 : 0;
```
- 실증: 비정상 1/총 100 → 종전 `50점·C` → **`43.8점·C`**(M8 12.5 → 6.25)
- 비정상 5/총 200(2.5%) → 종전 `50점·C` → **`37.5점·D`**(M8 0점)
- **0으로 나누기 예외도 함께 해소** — 총개체수 0 + 비정상 5 → 종전 양쪽 `DivideByZeroException` → 지금 `0·E`

**② 어류·저서 0종 → 점수 0 · 등급 E**
- 조사자: `CalculateFaiDetail(..., noSpeciesDeclared)` · `CalculateBmiDetail(..., noSpeciesDeclared)`
- 관리자: `GB.GetFAI` 는 **산출값(cluster)은 종전대로 두고 점수·등급만** 0·E로 바꾼다.
  `GB.GetBMI` 에도 같은 규칙을 넣었다 — 문서 §2-4는 `GetFAI`만 지목했지만,
  저서에 넣지 않으면 §2-3(저서 동일 원칙)과 "관리자·조사자를 함께 고친다" 원칙이 깨진다.
- 우선순위: **조사불가 > 0종 선언 > 미입력** (검증 완료)

**③ `출현종 없음(0종)` 선언 UI** — 어류·저서 지수 패널에 토글 + 안내문구.
선언 시 내보내기 게이트가 열린다(`CanExport`에 `NoSpeciesDeclared || IsUnavailable` 추가).
임시저장 Draft에도 선언값을 담는다.
