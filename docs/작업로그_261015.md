### 어류 저장 실패의 원인 (셀까지 특정함)

`어류_입력` 시트의 수식 16,964개를 Telerik 으로 하나씩 평가해 예외가 나는 셀을 모았다(곡교천 파일).

```
수식 셀 16964개 중 평가 예외 975개
  엑셀 69행 : 325개      ← FAI 100점 체계 M 항목
  엑셀 70행 : 325개
  엑셀 74행 : 325개
  예시 BY69 : =CHOOSE(BY$17, IF(BY$37=0,0,IF(BY$37=1,6.25,12.5)), …)
  같은 열 17행(하천차수) = ''   ← 비어 있음
```

- **옛 `CHOOSE(#REF!, …)` 블록(49~55행)은 원인이 아니다**(`_excel_formula_audit.md` §6-1 의 잔재). 그쪽은 평가돼도 터지지 않는다.
- 원인은 **현행 FAI 블록의 `CHOOSE(X$17, …)` 에서 인덱스 셀(17행 하천차수)이 빈 경우**다. Telerik 의 CHOOSE 구현이
  빈 인덱스를 받으면 `InvalidCastException(Double → RadExpression)` 을 던지고, Export 는 셀 자료형을 정하려고 모든 수식을
  평가하므로 통째로 실패한다. 하천차수가 채워진 열(Q~BX)은 정상이다.
- 생태현황 어류가 저장되는 이유: 그 파일은 레코드 열 대부분이 수식 대신 **값으로 붙여넣어져** 있다(같은 행 CHOOSE 가 386개 → 49개).

### 왜 B-7 전체를 멈추는가

- 내장본은 레코드 영역의 상수를 지운다(1단계 2). 그러면 **모든 레코드 열의 17행이 비어** 어류 양식은
  ① `tools\TemplateGen` 이 Telerik 으로 저장할 수 없고, ② 설령 다른 방법으로 만들어도 앱이 첫 레코드 열(Q)만 채워
  **나머지 385열의 17행이 빈 채로 저장**하므로 어류 일괄입력 내보내기가 매번 실패한다. 하천차수를 비워 둔 조사도 마찬가지다.
- 피하려면 **양식의 수식이나 구조를 바꾸거나**(예: 레코드 열을 Q 하나만 남김 · 빈 하천차수에서도 터지지 않게 CHOOSE 를 감쌈),
  **다른 엑셀 라이브러리**를 써야 한다. 둘 다 지시서 §9 에 따라 사용자 결정 사항이라 **B-7 은 여기서 멈춘다**.
  1단계(TemplateGen)·2단계(exporter 교체)·3단계(bulk_check)는 하지 않았다.

### 사용자 결정이 필요한 것

1. **어류 양식** — 아래 중 하나를 골라 주면 B-7 을 이어 간다.
   - (가) 내장본의 레코드 열을 **Q 한 열만** 남긴다 + 하천차수가 비면 저장 전에 알리고 막는다.
     양식 구조가 바뀌지만 수식 내용은 그대로다. 관리자 Import 는 Q 열부터 읽으므로 영향 없음(§3-5).
   - (나) 내장본의 FAI `CHOOSE(X$17,…)` 를 `IF(X$17="","",CHOOSE(…))` 처럼 **감싼다** — 수식 내용을 바꾸는 것이라 발주처 양식과 달라진다.
   - (다) 어류만 현행 방식(빈 통합문서) 유지 + 라벨 열만 덧붙인다 — 양식 내장은 아니다.
   - (라) 다른 엑셀 라이브러리 도입 — 새 NuGet, 별도 합의 필요.
2. **`License` 시트** — 현행 내보내기에도 붙어 있다. 없애려면 `Telerik.Licensing` 패키지와 라이선스 키가 필요하다(새 NuGet).
3. **생태현황 어류 `EA41` 배열수식** — 같은 행의 다른 열은 모두 일반수식이고 `SUMPRODUCT` 는 배열 입력 없이도 같은 값을 내므로
   실질 차이는 없을 것으로 본다(검증은 하지 않음). 원본 쪽의 우연한 배열 입력으로 보인다.

## B-4. 그리드 국명에 목록 밖 종을 치면 저장되지 않음

- 원인 확인: 편집기는 `SelectedItem` 만 바인딩, 목록 밖 국명은 `SelectedItem=null` → 행 setter 가 null 을 무시 → 친 글자 소실. 관찰형 3종도 같았다.
- 조치: 국명 셀 편집이 **확정되는 순간** 편집기의 `SearchText` 를 읽어 행 `SpeciesKo` 에 넣는다(`IQuickAddHost.ApplyTypedSpecies`).
  목록에 있는 이름이면 국명 변경 훅이 공식 종목록과 잇고(학명·길드 자동), 없으면 그대로 남는다. 빈 글자로 확정하면 기존 국명을 지우지 않는다.
- **지시서와 다르게 한 점** — 지시서는 "검색 텍스트를 `SpeciesKo` 에 바인딩"이었으나, `SearchText` 양방향 바인딩 + 커스텀 필터는
  목록 선택에 두 번 클릭이 필요해진다(90_TECH_NOTES §2 실측). B-2 완료 조건(한 번 클릭)과 부딪혀 **확정 때 한 번 읽는 방식**으로 했다. 완료 조건은 같다.
- **지시서와 코드가 다른 점** — "기존 미등재 경고 경로"가 없었다. 어류·저서에는 개체수가 있을 때만 뜨는 '과거 기록 없음'만, 관찰형에는 경고가 전혀 없었다.
  → 어류·저서: 행 경고 `종목록에 없는 국명 — 오타인지 확인하세요` + 상태줄 `목록 밖 국명 n건`. 관찰형: 국명 칸 `목록 밖` 뱃지(+툴팁).
- 어류·저서 VM 에는 지시서가 전제한 `OnRowPropertyChanged`(국명 → 종목록 매칭)가 **없었다** — 추가했다. 목록 밖 이름으로 고치면 예전 종의
  학명·길드가 남지 않게 `SelectedSpecies` 를 비운다(국명은 그대로).
- 하네스 확인: 새 행 `가나다벌레` → 보존·경고 / JSON 왕복 후 보존·경고 / 관찰형 `가나다새` 보존·`목록 밖` 표시·왕복 / 목록 종으로 고치면 학명 자동 /
  B-1 합산 키에도 이 국명이 쓰임.

## B-2. 국명 입력 중 받침이 다음 글자로 넘어감

- 메타데이터 확인: `RadAutoCompleteBox.AutoCompleteMode` = {Suggest, Append, SuggestAppend}, **기본값 SuggestAppend**(글자를 채운다) ·
  `IsHighlighted` 기본 False · `TextSearchMode` 기본 StartsWith.
- **재현 조건(기전 재현)** — 그리드와 같은 종목록·초성 필터를 단 기본값(SuggestAppend) 편집기에 글자를 흘렸다(한글 입력기 없이 완성 글자 단위):
  ```
  [SuggestAppend] '바' 입력 → 글상자 '바다살이민물담치' (선택 1,7)   ← 첫 후보로 나머지를 채우고 그 부분을 선택
  [SuggestAppend] 이어서 'ㅇ' → 글상자 '바ㅇ'
  [SuggestAppend] '가' 입력 → 글상자 '가는무늬하루살이' (선택 1,7)
  [SuggestAppend] 이어서 'ㅇ' → 글상자 '가ㅇ'
  ```
  실제 한글 입력기에서는 `바` 를 조합하는 중에 편집기가 글자를 채우면서 조합이 확정되고, 다음 자모 `ㅇ` 이 새 글자로 시작된다 → `바ㅇ`.
  원문 증상(`바ㅇ`·`가ㅇ`)과 첫 후보(`바다살이민물담치`·`가는무늬하루살이`)까지 일치한다.
  ⚠ 실제 한글 입력기(IME) 조합은 재현하지 못했다(사용자 PC 키보드를 건드리지 않기 위해). **최종 확인은 직접 입력으로 해야 한다.**
- 조치: 5개 그리드 국명 편집기에 `AutoCompleteMode="Suggest"`(제안만, 글자를 채우지 않음). 2단계(IME 조합 중 필터 지연)는 하지 않았다 — 1단계로 기전이 사라짐.
- 하네스 확인: `바`·`가` 입력 후 글자 그대로(선택 0) · `방울하루살이`·`강하루살이` 전체 입력 그대로 · 드롭다운 항목 **한 번 클릭으로 선택**.
- 빠른추가 콤보: `IsTextSearchEnabled=False` 라 글자를 채우지 않는다(같은 증상 없음). 다만 B-3 에서 드롭다운을 자동으로 열면서
  `SelectAllTextEvent` 기본값(All — 드롭다운이 열릴 때 글자 전체 선택)이 다음 글자를 덮어쓰게 만들 수 있어 `GotFocus, SelectionChanged` 로 좁혔다.

## B-3. 빠른추가에 종명을 쳐도 보기가 안 나옴

- 원인 ① (지시서대로) `FilterQuick` 이 검색어마다 `FilteredQuick` 을 새 List 로 교체 → 콤보 ItemsSource 교체.
  → `RadObservableCollection` 하나를 두고 내용만 바꾼다(알림 1회). 콤보 종류는 그대로.
- 원인 ② (**지시서에 없던 것 · 저서동물만**) `BenthosEntryViewModel` 이 `_speciesListSource` 를 **다시 선언**해 기반 클래스 속성을 가리고 있었다.
  화면(편집기·종목록)은 파생 속성을 보지만 빠른추가 필터는 기반 속성(빈 목록)을 보므로 **저서 빠른추가 후보가 항상 0개**였다. 재선언을 지웠다.
- 검색어가 비어 있지 않게 바뀌면 콤보 코드비하인드가 드롭다운을 연다(목록에서 고른 직후 종명으로 바뀐 글자에는 열지 않는다).
- 키보드 흐름 확인: `ㅍㄹㅁ`/`피라미` → 즉시 열림·후보 → **↓ 가 첫 후보를 바로 고르고 개체수 칸으로 이동**(Telerik 기본 동작, 종전과 같음) →
  개체수 → Enter → 행 추가·검색창 복귀·검색창 비움. **Enter 만으로도 고를 수 있게** 했다 — 친 글자와 이름이 똑같은 종, 없으면 후보가 하나뿐일 때만
  (후보가 여럿이면 고르지 않는다: `참갈겨니` 를 치려다 `갈겨니` 가 들어가는 것을 막기 위해).
- 저서: `ㅂㅇㅎ`·`방울` 즉시 열림·`방울하루살이` 후보 확인.
- 기록: ↓ 가 곧바로 첫 후보를 고르므로 **↓ 로 두 번째 후보로 내려갈 수는 없다**(종전과 같음). 두 번째 후보는 마우스로 고르거나 글자를 더 친다.

## B-6. 하상구성 — 정수만, 저서에도 합계 경고

- `Behaviors\IntegerInput.cs`(attached) — 숫자 외 글자·공백 키·붙여넣기 차단, 최댓값(하상 100) 초과 차단, 그 칸에서 한글 입력기 끔.
  엑셀 셀 복사(`30⏎`)는 앞뒤 공백을 걷어 받아들인다. 저장형은 문자열 그대로(세션 호환).
- 적용: 어류·저서 하상 8칸(0~100) · 저서 Surber30/50·드렛지·에크만 · 어류 채집시간(분) — 정수(상한 없음).
- 저서 합계 경고: 어류 구현을 그대로 옮김(`SubstrateTotal`·`SubstrateWarning`) — 펼친 화면 머리글 옆 + **접힌 요약줄**에도 표시. 8칸이 모두 비면 경고하지 않는다.
- 예전 세션의 소수·문자 값: 지우지 않고 경고 — `0~100 정수가 아닌 칸: 모래 12.5` · `채집시간 30.5 — 분 단위 정수로 고치세요` · `채집기 횟수가 정수가 아닌 칸: Surber 30 1.5`.
- 공용 문구 스타일 `InlineWarnTextStyle`(비면 접힘 · 잘리면 툴팁) — 색 조합(`DangerOnSurface`/흰)을 대비 감사에 등록.

## B-8. 어류 「흐름상태(채집)」 입력칸

- 공용 `Views\UserControls\MultiChoiceBox`(C-4 에서 다시 씀) — `RadComboBox` `AllowMultipleSelection`(design.md §7 의 콤보, Style 통째 지정 없음).
  화면은 `Options`·`Value` 만 넘긴다. 저장값은 **양식 순서대로 공백 없이 `,`**(`흐름,소`), 아무것도 안 고르면 null.
- 예전 값: `,`·`.` 로 나눠(관리자 Import 와 같은 구분자) 맞는 것은 선택 상태, 안 맞는 것은 `1 (양식 외)` 항목으로 **선택된 채 남기고** 아래에 경고.
  화면을 열기만 하면 저장값을 다시 쓰지 않는다(`여울, 1` 그대로). 조사자가 그 항목을 직접 해제해야 값에서 빠진다.
- 라벨: 입력칸·요약줄 모두 「흐름상태(채집)」(양식 16행)과 「유속」(28행 `HabitatFlowState`)으로 나눔. 요약줄에 흐름상태(채집) 값 추가.
- 일괄입력용 16행(Q열)에 `흐름,소` 가 이름 그대로 들어가는 것 확인(현행 exporter — B-7 은 멈춤 상태).
- 기록: 보고서용 엑셀(`FishReportExporter`)의 라벨 `흐름상태`·`흐름상태(서식처)` 는 이번 범위가 아니라 그대로 두었다(기준 엑셀 대조도 그대로 일치).

## B-5. 닫을 때 저장 확인

- `SessionService` 스냅샷 — 조사개황 + 자료가 있는 분류군을 세션 JSON 과 같은 방식으로 직렬화(저장과 같은 기준). 저장 시각은 겉봉에만 있어 빠진다.
  **접힘(`…Expanded`)과 방금 추가 강조(`IsJustAdded`)는 세션에 실려도 비교에서 뺀다**(화면 상태).
- 기준 갱신: 앱 시작(편입·예시 시드가 끝난 뒤, 창 Loaded) · `SaveCurrentAsync` 성공(저장한 바로 그 내용) · `LoadAsync` · `CopyToSite` · `CopyFromPreviousAsync`.
- 창 닫기: 변경이 있으면 `현재 입력 사항을 저장할까요?` [예/아니요/취소], 기본 [예].
  [예] → 닫기 멈춤 → 저장 → 성공하면 다시 닫음(재진입 플래그 · 다음 차례에 Close) / 실패하면 사유를 알리고 창 유지. [아니요] → 닫음. [취소] → 유지.
- `SaveCurrentAsync` 빈 값 동작 확인: 대분류·연도차수·지점이 비어도 **`무제_무제_무제` 같은 키로 저장해 버린다**(다른 무제 세션을 덮어쓸 수 있음).
  → 닫기·자료함 확인에서 [예]를 눌렀는데 이 셋 중 빈 칸이 있으면 **저장하지 않고** `비어 있는 칸: 대분류 · 연도차수 · 지점` 을 알리고 멈춘다.
  기존 [임시 저장] 단추의 동작은 바꾸지 않았다.
- 자료함 [불러오기]·[지점 복사]·[차수 복제] 앞에도 같은 확인(질문 아래에 무엇이 바뀌는지 한 줄). [예]로 저장했으면 목록을 새로 읽고 고르던 세션을 다시 고른다.
- 하네스 확인(가짜 저장소): 변경 없음 → 묻지 않음 / [취소] 유지 / [아니요] 저장 없이 닫힘 / 접힘만 바꿈 → 변경 아님 / 저장 키 비어 있음 → 안내·유지 /
  저장 실패 → 안내·유지 / [예] → 저장 후 닫힘 / **예시 3건 각각 불러온 뒤 7개 분류군 화면을 모두 띄워도 변경 없음 → 묻지 않음** /
  자료함 세 동작 [취소] 그대로 · [아니요] 저장 없이 진행 · [예] 저장 후 진행.
