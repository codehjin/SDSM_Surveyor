## 2. 불일치 상세

### ⚠ 불일치 1 — 어류 조사 결과가 0일 때 (6건) · **실무 영향 있음**

| 입력 | 관리자 | 조사자 |
|---|---|---|
| 빈 목록 / 전부 0개체 / 전부 null (차수3) | **37.5 · D등급** | **(null) · 등급 없음** |

- **원인**
  - 조사자 `Ecology\EcologyCalculator.cs:95~99` — 총출현종수가 0이면 점수·등급을 산출하지 않는다.
  - 관리자 `GB.cs:601~`(`GetFAI`) — 0 가드가 없다. 자료가 비어도 M4(내성 0%)·M5(잡식 0%)·M8(비정상 0%)이
    **각각 만점 12.5를 받아** 합계 37.5 → D등급이 된다.
- **성격**: 조사자 쪽이 **의도적으로 넣은 가드**다(빈 조사에 "37.5 D"가 뜨면 조사자가 오해한다는 이유).
- **판단 근거**: 어류가 한 마리도 없는 지점이 "D(약간 나쁨)"으로 기록되는 것은 지침 취지에 어긋난다.
  0종은 최악이거나 **평가 불가**이지 중간 등급이 아니다.
- **⚠ 사용자 결정 필요** — 아래 §3-1 참조.

### ⚠ 불일치 2 — BMI가 음수일 때 등급명 (1건) · 실무 영향 없음

| 입력 | 관리자 | 조사자 |
|---|---|---|
| 오탁치 s=6 (BMI 음수) | `Check` | `E` |

- **원인**: 관리자 `GB.cs:569` 는 음수면 `"Check"`, 조사자 `Ecology\BenthosCalculator.cs:149` 는 `"E"`.
- **성격**: BMI = `(4 − Σ(s·g·h)/Σ(g·h)) × 25` 이므로 **오탁치 s > 4** 여야 음수가 된다.
  실제 종목록(`BenthosSpeciesList`)의 오탁치는 0~4 범위라 **정상 데이터에서는 발생하지 않는다.**
- **판단**: 낮은 우선순위. `SDSM_Core` 통합 시 관리자 쪽(`Check`)으로 맞추면 된다(데이터 이상 신호를 남기는 편이 안전).

### ⚠ 불일치 3 — HRI: 관리자 **편집화면**과만 다름 (5건) · **관리자 내부 문제**

조사자는 관리자 **일괄입력 경로(= DB에 실제로 저장되는 값)와 32건 전부 일치**한다.
차이가 나는 상대는 관리자 앱의 *편집화면* 로직이며, 이는 관리자 앱 안에서 두 구현이 서로 다르기 때문이다.

|---|---|---|---|
| 평가항목 전부 미입력 / 전부 0 | 점수 `0` · 등급 `E` | 점수 `(null)` · 등급 `(null)` | 점수 `(null)` · 등급 `(null)` |
| 조사불가 = `"접근 불가"`(공백 포함) | 등급 `A` ← **미검출** | 등급 `-` | 등급 `-` |

  - 편집화면 `SDSM_App\ViewModels\Editors\HabitatWaterEdgeEditorControlViewModel.cs:317~`
    - 합이 0이면 점수를 `0`으로 둔다(일괄입력은 `null`).
    - 조사불가 비교에서 **공백을 제거하지 않는다** → `"접근 불가"`를 못 잡는다.

## 3. 불일치는 아니지만 함께 발견한 문제

### ⚠ 3-1. M8 비정상종 비율 — **양쪽 모두 정수 나눗셈** (지침 위반)

| 비정상 개체수 / 총개체수 | 실제 비율 | 양쪽 계산 결과 | M8 배점 |
|---|---|---|---|
| 1 / 100 | 1 % | **0 %** | 12.5 (만점) |
| 5 / 200 | 2.5 % | **0 %** | 12.5 (만점) |
| **199 / 200** | **99.5 %** | **0 %** | **12.5 (만점)** |
| 200 / 200 | 100 % | 100 % | 0 |

- **원인**: 관리자 `GB.cs:637`, 조사자 `Ecology\EcologyCalculator.cs:68` — 둘 다 `int / int` 정수 나눗셈이다.
  ```csharp
  double 비정상개체수비율 = 비정상개체수 != 0 ? (비정상개체수 / 총개체수) * 100 : 0;
  ```
  → **비정상 개체수가 총개체수 이상일 때만 0이 아닌 값**이 나온다. 사실상 M8은 항상 만점이다.
- **양쪽이 같으므로 "불일치"는 아니다.** 다만 지표가 작동하지 않는다.
- **사용자 결정 완료**: `SDSM\docs\ADMIN_TASKS.md` §6 — 지침에 따라 **실수 나눗셈으로 수정**하기로 결정됨.
  - ⚠ **반드시 관리자·조사자를 동시에 고쳐야 한다.** 한쪽만 고치면 지금 일치하는 값이 어긋난다.
  - 과거 데이터 재산출 여부는 같은 문서 §6-2의 사용자 판단 사항이다.
  - **이 문서 작성 시점에는 양쪽 모두 수정하지 않았다**(11_CALC_PARITY §6: 임의 수정 금지).

### ⚠ 3-2. 0으로 나누기 예외 — **양쪽 모두 발생**

| 입력 | 관리자 | 조사자 |
|---|---|---|
| 총개체수 0 + 비정상 개체수 5 | `DivideByZeroException` | `DivideByZeroException` |

- 위 정수 나눗셈 식에서 `총개체수 == 0` 이면 정수 나눗셈이라 **예외로 죽는다**(실수 나눗셈이면 Infinity).
- 조사자 앱은 화면(`FishEntryViewModel.Recalculate`)에서 유효 개체 0이면 계산을 부르지 않아 가려져 있고,
  관리자는 일괄입력 중 이 조합이 들어오면 **가져오기가 실패**할 수 있다.
- §3-1의 실수 나눗셈 수정 시 `총개체수 > 0` 가드를 함께 넣으면 동시에 해소된다.
