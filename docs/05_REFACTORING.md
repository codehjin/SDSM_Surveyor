### 0-2. 회귀 기준 파일 — **코드 픽스처로 만든다. 화면 입력이 아니다.**

리팩토링 후 셀 값이 같은지 대조할 기준 엑셀이 필요하다. 그런데 **현재 시험 데이터가 없다**
(`docs\_baseline\` 없음). 화면에서 손으로 7개 분류군을 채우는 방식은 재현이 안 되므로 쓰지 않는다.

**방식** — `tools\BaselineGen\` 에 콘솔 프로젝트를 하나 만든다.

1. 7개 분류군 VM을 **고정값으로** 채우는 픽스처를 코드로 작성한다(난수·`DateTime.Now` 금지).
   - 각 분류군 5~10행, 이상치 경고가 걸리는 값 1행, `null`과 `0`이 섞인 행 1행씩 반드시 포함
   - 어류는 비정상종(DE/EF/LE/TU) 값이 있는 행 1개 — **M8 실수 나눗셈 회귀를 잡는 유일한 케이스**
   - 0종(빈 조사) 케이스 1건 — `12_CALC_FIX.md` 의 E등급 판정 회귀 확인용
2. 14개 exporter를 직접 호출해 `docs\_baseline\` 에 저장한다.
3. 리팩토링 후 같은 픽스처로 다시 생성해 **셀 단위 대조**한다.
   대조도 스크립트로 한다(`tools\BaselineDiff\` 또는 python + openpyxl). 눈으로 비교하지 않는다.

> 픽스처는 **커밋한다.** 이 단계뿐 아니라 앞으로의 모든 회귀 확인에 쓴다.

### 2-0. 저장소가 분리된 상태에서의 배치 (결정 사항)

1단계에서 저장소를 분리한 결과, 조사자 앱이 `..\..\SDSM\SDSM_Models\SDSM_Models.csproj` 를
**상대 경로 ProjectReference로 참조**하는 크로스 저장소 의존이 드러났다.

**결정: 현행 "나란히 clone" 방식을 유지한다.** NuGet 패키지·git submodule은 도입하지 않는다.
- 이유: 유지보수 인력이 1인이고, 패키지 배포·버전 관리 비용이 얻는 것보다 크다.
- `SDSM_Core`와 `SDSM_Models`는 **관리자 저장소(`SDSM`)에 둔다.** 관리자가 원본 데이터·모델의 기준이기 때문이다.
- 조사자 앱은 지금처럼 상대 경로로 참조한다.

**대신 반드시 할 것 — 잘못 clone했을 때 원인을 바로 알 수 있게 한다.**
- 두 저장소 각각에 `README.md` 를 만들어 **폴더 구조와 나란히 clone 요구사항**을 최상단에 명시
  ```
  <상위폴더>\
    SDSM\            (관리자, 공용 모델·SDSM_Core 포함)
    SDSM_Surveyor\   (조사자)
  ```
- `SDSM_Surveyor_App.csproj` 에 참조 경로가 없을 때 **친절한 빌드 오류**를 내는 `Target` 추가
  예: `<Error Condition="!Exists('..\..\SDSM\SDSM_Models\SDSM_Models.csproj')" Text="SDSM 저장소를 같은 상위 폴더에 나란히 clone해야 합니다." />`

> 훗날 조사자 앱을 외부에 단독 배포해야 하는 상황이 오면 그때 NuGet 분리를 재검토한다. 지금은 하지 않는다.

## 4. 엑셀 계산식 검수 (미완 과제)

조사자 제출 엑셀에 들어 있는 **수식 자체**가 내부 코드 로직과 같은 정의인지 셀 단위로 대조한다.
- 확인된 사실: 관리자는 엑셀의 지수 "값"을 무시하고 **원자료로 재계산**한다.

- 차이가 있으면 **지침(수생태계 건강성 평가 방법)을 기준**으로 코드를 채택하고, 차이를 `90_TECH_NOTES.md` §5에 기록한다.
