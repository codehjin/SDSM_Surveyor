> `12_CALC_FIX.md` 의 정수 나눗셈 수정이 원본 엑셀과 일치함을 확인했다.

### 2-2. M1~M8 배점 (행68~75)

`CHOOSE(하천차수, …)` 7분기 = 차수 1~7. 코드는 `switch`.

| M | 엑셀 | 코드 | |
|---|---|---|---|
| M1 국내종 종수 | 차수1 `<=1→0, =2→6.25, else 12.5` … 차수7 `<=11→0, <=22→6.25, else 12.5` | `GetM1` 7분기 | ✅ 전 구간 동일 |
| M2 여울성저서종수 | 차수1 `=0→0, =1→6.25, else 12.5` … | `GetM2` | ✅ |
| M3 민감종수 | 차수1 `=0→0, <=2→6.25, else 12.5` … | `GetM3` | ✅ |
| M4 내성종 비율 | `>70→0, >=30→6.25, else 12.5` | `v>70?0:(v>=30?6.25:12.5)` | ✅ |
| M5 잡식종 비율 | `>70→0, >=30→6.25, else 12.5` | 동일 | ✅ |
| M6 충식종 비율 | `<20→0, <=45→6.25, else 12.5` | 동일 | ✅ |
| M7 국내종 개체수 | 차수1 `<=10→0, <=20→6.25, else 12.5` … | `GetM7` | ✅ |

> **경계 부등호까지 같다.** M4·M5는 `>=30`(이상), M6는 `<=45`(이하), M8은 `>0`(초과).

### 2-3. 총점·등급 (행76~78)

| 행 | 엑셀 | 코드 | |
|---:|---|---|---|

## 5. ⚠ 서식수변 HRI — 불일치 1건

### 5-1. 일치하는 부분

| 항목 | 엑셀 | 코드 | |
|---|---|---|---|
| 평가점수 | `=ROUND(SUM(F17:F26)/2, 1)` | `Math.Round(total/2, 1, AwayFromZero)` | ✅ |
| 조사불가 | `=IF(F14="접근불가","-",F27)` — **접근불가 하나만** | `Contains("접근불가")` | ✅ |
| 등급 | `>=80"A" >=60"B" >=40"C" >=20"D" >=0"E"` | 동일 | ✅ |

> 어류 FAI는 조사불가 사유가 **4종**(접근불가·건천화·준설·공사중)인데
> 서식수변은 **접근불가 1종**뿐이다. 엑셀·코드 모두 그렇다. **의도된 차이이므로 통일하지 말 것.**

### 5-2. 불일치 — 합계 0

```csharp
// SDSM_Core\Ecology\HabitatEvaluator.cs
double total = arr.Where(x => x.HasValue).Sum(x => x!.Value);
double? score = total != 0                       // ← 여기
    ? Math.Round(total / 2, 1, MidpointRounding.AwayFromZero)
    : null;
```

| 상황 | 엑셀 | 코드 | |
|---|---|---|---|
| 10개 항목 **전부 미선택** | `SUM=0` → 0점 → **E** | `null` → 등급 `null` (화면 `-`) | 코드가 타당 |
| 10개 항목 **전부 0점 선택** | `SUM=0` → 0점 → **E** | `null` → 등급 `null` (화면 `-`) | ❌ **코드가 틀림** |

**엑셀은 두 경우를 구분할 수 없다**(빈칸도 `SUM`에서 0). 코드는 `null` 로 구분하려 했으나,
합계가 0인지만 보기 때문에 **0점을 선택한 것까지 미입력으로 뭉갠다.**

### 5-3. 이것이 실제로 발생하는가 — **발생한다**

`HabitatWaterEdgeEntryViewModel.Opt1~Opt10` 을 확인한 결과 **10개 항목 전부에 `0` 선택지가 있다.**

| 항목 | 0점 선택지 |
|---|---|
| 1 자연적 종횡사주 | 없음 |
| 2 하도 자연성 | 인공 직강화 |
| 3 유속 다양성 | **건천화** |
| 4 하천변 폭 | ≤ 0.5 |
| 5 저수로 하안공 | 콘크리트(불투수) |
| 6 제방하안 재료 | 하안블록/콘크리트 |
| 7 저질 상태 | 콘크리트 |
| 8 횡구조물 | 어도없음/파손 |
| 9 제외지 토지이용 | 주차장/불투수 |
| 10 제내지 토지이용 | 1/2↑ 시가지 |

**콘크리트로 직강화된 도시하천이면 10개 항목이 전부 0점이 나온다.** 가공의 사례가 아니다.

> **결과: 가장 훼손된 하천이 평가를 못 받는다.** 0점·E등급이어야 할 지점이 `-`(미평가)로 나온다.
> 구조가 `12_CALC_FIX.md` 의 FAI 0종 문제(내성종 0%가 만점을 받아 37.5·D)와 **정확히 같다.**

### 5-4. 수정안

합계가 아니라 **선택 여부**로 판정한다.

```csharp
var arr = items.ToArray();
bool anySelected = arr.Any(x => x.HasValue);      // ← 판정 기준 교체
double total = arr.Where(x => x.HasValue).Sum(x => x!.Value);

double? score = anySelected
    ? Math.Round(total / 2, 1, MidpointRounding.AwayFromZero)
    : null;                                        // 전부 미선택일 때만 null
```

- 전부 미선택 → `null` · 등급 `null` (**변경 없음** — 엑셀보다 정확한 동작을 유지)
- 전부 0점 선택 → `0` · 등급 `E` (**엑셀과 일치**)
- 일부만 선택 → 선택분 합계 ÷ 2 (**변경 없음**)

### 5-6. 과거 데이터 영향 — **바뀌는 레코드 0건** (2026-08-22 측정)

관리자 DB 사본(`SDSMDB.sqlite` 2026-07-16, 1,720,320 bytes)을 **읽기 전용**으로 열어 `HabitatWaterEdge` 90건 전부를 확인했다.
원본은 열지 않았다 — 사본을 뜬 뒤 `mode=ro` 로만 접근해 `-wal`/`-shm` 이 생기지 않았다.

| 항목 | 건수 |
|---|---:|
| 전체 `HabitatWaterEdge` 레코드 | **90** |
| 10개 항목 모두 입력 + 합계 0 → `-` 에서 `0·E` 로 **바뀌는** 레코드 | **0** |
| 일부만 입력 + 합계 0 → 역시 바뀌는 레코드 | **0** |
| 전부 미입력 → 변화 없음 | **0** |
| 합계 > 0 → 변화 없음 | **90** |

**재계산·정정이 필요한 자료는 없다.** 90건 모두 합계가 0보다 크다(최소 48.0 → 24.0·D, 최대 153.0 → 76.5·B).

함께 확인한 것:

- **항목이 `null` 인 레코드가 하나도 없다**(90건 전부 10개 항목이 채워져 있다). 관리자 DB 에는 아직 "미평가" 상태가 없다.
- **0점 항목 자체는 실제로 쓰인다** — 24건(90건 중 27%)이 항목 중 하나 이상에 0점을 골랐다.
  항목별로는 10 제내지 토지이용 20건, 1 자연적 종횡사주 9건, 8 횡구조물 6건, 2 하도 자연성 4건, 4 하천변 폭 1건.
  한 레코드에서 0점이 가장 많은 경우가 **3개**(`원천리천3`, 합계 66.0)다.
  → §5-3 의 "가공의 사례가 아니다" 는 맞다. 다만 **10개가 전부 0점인 지점은 아직 들어오지 않았다.**
- 저장된 `EvaluationScore`·`EvaluationGrade` 를 현행 계산식으로 다시 계산해 대조 — **90건 전건 일치**(불일치 0).
  즉 DB 값은 지금 코드가 낸 값과 같고, 이번 수정으로 어긋나는 과거 자료는 없다.
- 조사불가 사유가 적힌 레코드 0건.

> 요약: **이번 수정은 과거 자료를 하나도 건드리지 않는다.** 앞으로 들어올 자료(콘크리트 직강화 도시하천)에만 적용된다.

## 6. 원본 엑셀의 결함 (참고 — 우리 코드와 무관)

### 6-1. 구버전 FAI 블록이 깨져 있다

`어류_입력` 행49~56(구 8메트릭 40점 체계)이 **`=CHOOSE(#REF!, …)`** 다. 참조가 끊겨 있다.

```
행49  M1 =CHOOSE(#REF!,IF(T$36<=1,1,IF(T$36=2,3,5)), …)
행57  모델값(DB용) =SUM(Q$49:Q$56)      ← #REF! 전파
행58  모델값 =IF(C34=0,8,C57)
행59  건강도등급 =IF(Q$58>=36,"A", …)
```

현행 100점 체계(행68~78)는 `CHOOSE(X$17, …)` 로 **하천차수를 정상 참조**하므로 영향이 없다.
구 블록은 사용되지 않는 잔재로 보이나, **원본 엑셀 파일의 문제이므로 우리가 고칠 대상은 아니다.**
조사자에게 양식을 다시 배포할 일이 있으면 그때 정리하면 된다.

### 6-2. 행 라벨과 수식 내용이 어긋난다

`행38` 라벨은 `내성도` 인데 수식은 `SUMPRODUCT(($B="SS")*…)` 로 **민감종수**를 센다.
`행40` 라벨은 `섭식특성` 인데 **잡식종 비율**이다. 라벨만 부정확하고 계산은 맞다.

→ 엑셀 라벨을 근거로 코드를 고치면 안 된다. **수식이 기준이다.**

```bash
# 수식 추출 — data_only=False 로 열어야 수식이 보인다(True면 캐시된 값만 나온다)
python3 -c "
import openpyxl

"
```

- ⚠ 원본 엑셀을 **열기만 하고 저장하지 않는다.**
