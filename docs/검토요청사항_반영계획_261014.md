## 1차 — 버그

### B-1. 같은 종 2번 입력 시 계산이 틀어짐  [영향 큼]
- 계산이 전부 행 단위(`SDSM_Core\Ecology` 에 `GroupBy` 0건) → 종수 과대, 저서 **오탁치·지표가중치 이중 합산**
- 조치(10-15 개정): 종이 들어가는 **5개 분류군 모두** 입력 시점에 처리. 어류·저서는 **합산**, 조류·포유류·양서파충류는 **행은 넣고 경고**(한 행 = 관찰 1건이라 위치가 다르면 같은 종 여러 행이 정상)
- 규칙: 기존 개체수 + 새 개체수. 둘 다 비면 비운 채(결측 보존). 합산 사실을 '방금 추가' 칩에 표시

### B-2. 국명 입력 중 받침이 다음 글자로 넘어감
- `RadAutoCompleteBox` 자동완성이 IME 조합 중 텍스트를 덮어씀 → 조합 중엔 치환 중지

### B-3. 빠른추가 드롭다운이 타이핑으로 안 열림
- `IsFilteringEnabled=False` + 여는 트리거가 `OpenDropDownOnFocus` 뿐, 매 글자 `ItemsSource` 교체
- 조치: 검색어 변경 시 직접 열기 + 컬렉션 갱신 방식으로 (컨트롤 교체 금지 주석 준수)

### B-4. 그리드 국명에 목록 외 종을 못 넣음

## 회신에 짚을 것

1. **하상구성 암반·콘크리트** — 종이 야장엔 없지만 DB 일괄입력 양식(2026-03)에는 있음. 앱은 DB 양식에 맞춰 유지하고, 쓰지 않으면 비워 두면 됨. (어류는 콘크리트를 실제 26건 사용)
2. **흐름상태 비율** — 양식은 여울/흐름/소 **복수 선택**. 비율 입력은 양식에 없어 반영하지 않음. 필요하면 양식 개정 요청
3. **채집 횟수** — 저서동물은 양식에 이미 도구별 조사회수 칸이 있음(앱에 반영). 어류는 양식에 횟수 칸이 없음
4. **"일괄입력용에 숫자만 나온다"** — 앱 쪽 문제였음. 라벨 없이 값만 내보내고 있었음 → 최종본 양식 그대로 내보내도록 수정
5. **개체밀도** — 서버넷·드렛지·에크만은 입력·저장만 되고 계산에 안 쓰임. 이번엔 실측 개체수 유지, 환산식·면적 규약을 주시면 반영
6. **실제 제출 자료의 오류**(참고로 알림) — 하상구성 합계 90%·200% 26건, 곡교천 권역 20건이 한강/안성천으로 입력됨
