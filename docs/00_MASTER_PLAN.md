## 0. 작업 체계

| 역할 | 담당 | 산출물 |
|---|---|---|
| 계획 수립 | 기획 AI | `docs/*.md` |
| 코딩 | **Claude Code** | 실제 코드 |
| 디자인 설계 | **Claude Design** | 디자인 스펙 → `docs/06_DESIGN_REBUILD.md` 갱신 |

**작업 지시 방법**: `docs/<파일명>.md 를 읽고 그대로 작업해줘.`

**작업 순서 규칙**
1. 어떤 작업이든 시작 전 **`docs/90_TECH_NOTES.md` 를 반드시 먼저 읽는다.** (검증된 API·함정 모음)
2. 한 문서를 끝내면 그 문서 하단 **체크리스트를 갱신**하고 커밋한다.
3. 빌드가 통과하지 않은 상태로 다음 단계로 넘어가지 않는다.

## 1. 프로젝트 개요

**목적**: 기존 엑셀 일괄입력 방식은 보고서용 계산식을 모두 포함해 입력이 복잡하고, 사업별 엑셀이 연 30개 이상 관리자 PC에 쌓인다. 조사자 전용 입력 프로그램으로 입력·계산을 대체하고, 결과를 관리자 프로그램의 분류군별 테이블로 넘긴다.

**구성**
- `F:\desktopSW\samsung\1_program\SDSM\` — **관리자 앱**(삼성 담당자 취합용). .NET 8 WPF + Telerik + EF Core/SQLite.
- `F:\desktopSW\samsung\1_program\SDSM_Surveyor\` — **조사자 앱**(현장 입력, 완전 오프라인). 본 작업의 주 대상.

**핵심 원칙**
- 조사자는 **자동계산 필드를 제외한 모든 항목**을 입력한다. (필드 목록: `02_FEATURE_SCREENS.md`)
- "단순화" = 항목 축소가 아니라 **반복입력 축소**.
- 자동계산 필드는 관리자가 재계산하므로 일괄입력 엑셀에는 넣지 않는다.
- 결측치(`null`)와 `0`(실측 부재)을 엄격히 구분한다.
- 이상치 경고는 **알림일 뿐 제재가 아니다** — 저장·내보내기를 막지 않는다.

## 2. 현재 상태 (완료된 것)

**조사자 앱**
- 7개 분류군 입력 화면 존재(어류·저서동물·조류·포유류·양서파충류·서식수변·수질)
- **어류·저서동물**: 관리자 전체 필드 확장 + 접이식 조사개황 + 종 빠른추가 바 + 엑셀 붙여넣기 완료
- 공통 조사개황 중앙화: `Models/SurveyMeta.cs` + `Views/UserControls/SurveyOverviewControl.xaml`
- 종목록 외부화: `species.json`(어류253·저서803·조류169·포유류17·양서파충류22) + `Data/SpeciesListProvider.cs`
- 이상치 경고: `reference.json` + `Data/ReferenceRangeProvider.cs`
- 비동기 동기화: 교환소 폴더 + 버전비교 + 가져오기 (`Data/SyncService.cs`, `Views/Windows/SyncWindow.xaml`)
- 계산 로직: `Ecology/` (FAI·BMI·DI/H'/R1/J'·수질등급·HRI) — 관리자 `GB.cs`와 동일 결과 확인
- 엑셀 내보내기: 어류 보고서용 + 어류/저서 일괄입력용
- 탭 = RadioButton 세그먼트(관리자 통계화면과 동일 형식)

**미해결 (현재 빌드 오류)**
- `Export/FishReportExporter.cs` 의 AutoFilter 적용부. `IWorksheetFilter`가 internal이라 접근 불가.
  → 해결책은 `90_TECH_NOTES.md` §AutoFilter 참조. **해결 안 되면 필터를 제거하고 진행**(표 구조는 유지, 사용자가 엑셀에서 데이터>필터 1회 클릭).
