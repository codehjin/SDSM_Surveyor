# A. 조사지점 체계

## A-1. 원천 데이터 (확인 완료)

### ① 관리자 DB `SiteDivision` 테이블 — 4단계 구분
`SiteDivisionId | Project | Workplace | WorkplaceRiver | WorkplaceSite`

| Project | Workplace | WorkplaceRiver | WorkplaceSite |
|---|---|---|---|
| 생태현황 | (null) | (null) | (null) |
| 방류하천 | 기흥 | 오산천 | 오산 |
| 방류하천 | 화성 | 원천리천 | 원천리천 |
| 방류하천 | 온양 | 곡교천 | 곡교천 / 천안천 / 회룡천 |

→ 내보내기 구분 컬럼: **프로젝트명 · 사업장 · 과업대표하천 · 지점명**

### ② 제출 엑셀 템플릿의 `조사지점` 시트 — 지점 마스터
예: `일괄입력자료\2602_방류하천_곡교천_어류_DB_v1.xlsx` → 시트 `조사지점`(행3부터)

| 열 | 내용 | 예 |
|---|---|---|
| B | 지점설명 | 배방야구장 |
| **C** | **DB상 지점명** | **곡교천1** |
| D | 위도(DMS) | 36°45'47.09"N |
| E | 경도(DMS) | 127°5'26.18"E |
| F | 연도별 보고서상 지점명(22~25) | 곡교천-1 |
| G | 연도별 보고서상 지점명(26) | 곡교천1 |
| **H** | **조사장소 번호** | **St.1** |
| I | 비고 | 수질만 |

→ **`ST1 → 곡교천1` 변환의 근거가 H열 ↔ C열이다.**
→ **연도별 지점명 변경 이력**이 F·G열이다(연도 구간별 표기).
→ 비고("수질만")로 **분류군별 적용 여부**를 구분한다.

## A-2. 구현

1. **지점 마스터 파일** `sites.json` 도입
   - 스키마: `{ Version, GeneratedAt, Sites:[{ Project, Workplace, River, SiteName, StNo, Desc, Lat, Lng, YearAliases:{ "22~25":"곡교천-1", "26":"곡교천1" }, Taxa:["수질"] }] }`
   - 로드 규칙은 `species.json`과 동일: `%AppData%\SDSM_Surveyor\sites.json` → 실행폴더 번들
   - 공유 모델은 `SDSM\SDSM_Models\` 에 `SiteCatalog` 로 추가(관리자와 공용)
   - 초기 데이터는 위 엑셀 `조사지점` 시트에서 생성한다(1회 변환).

2. **조사자는 등록된 지점만 선택**
   - `SurveyOverviewControl`의 지점명을 자유입력 → **드롭다운**으로 교체
   - 선택 시 하천명·좌표·사업장이 **자동 채워짐**
   - 대분류(방류하천/생태현황) 선택에 따라 지점 목록이 필터됨

3. **ST 번호 입력 허용 + 자동 변환**
   - 조사자가 `ST1`, `St.1`, `st 1` 로 입력해도 → **`곡교천1`로 정규화**해 저장·내보내기
   - 화면에는 `곡교천1 (St.1)` 처럼 함께 표시해 조사자가 인지하게 한다

4. **좌표 → 외부 지도 연결**
   - 지점 선택 시 좌표 옆 [지도] 버튼 → 기본 브라우저로 지도 열기
   - DMS(`36°45'47.09"N`) ↔ 십진수 변환 유틸 필요(엑셀은 DMS, 관리자 DB는 십진수)

5. **내보내기에 구분 컬럼 추가**
   - 보고서용 엑셀의 출현종·건강성평가 시트 맨 앞에
     `프로젝트명 | 사업장 | 과업대표하천 | 지점명` 추가(현재는 지점명만)

> 관리자 쪽 지점 관리 화면(등록·수정·병합·연도별 이력)은 `..\SDSM\docs\ADMIN_TASKS.md` 참조.

# B. 조사 세션 (자료함)

## B-1. 문제

현재 저장은 `%AppData%\SDSM_Surveyor\drafts\{분류군}.json` **단일 슬롯 덮어쓰기**다.
→ 지점을 바꾸면 이전 지점 자료가 사라지고, 불러오기 화면도 없다. 연 8개 지점을 감당할 수 없다.

## B-2. 개념

**조사 세션** = `대분류 + 연도차수 + 지점` 하나. 이 세션이 **공통 조사개황 + 7개 분류군 데이터**를 함께 보관한다.

## B-3. 구현

1. **저장 구조 개편**
   - `drafts\{분류군}.json` → `sessions\{sessionId}.json` (다건) + `index.json`(목록·메타)
   - `sessionId` = 대분류·연도차수·지점 조합(파일명 안전 문자로 변환)
   - `index.json` 항목: sessionId, 대분류, 연도차수, 지점, 하천, 최종수정일시, 입력된 분류군 목록, 경고 건수
   - **기존 draft 파일이 있으면 1회 마이그레이션**(첫 실행 시 세션 하나로 편입)

2. **자료함 화면**(신규 창 또는 첫 화면)
   - 세션 목록 그리드: 대분류·연도차수·지점·하천·최종수정·입력 분류군·경고
   - 검색·정렬, 행 더블클릭 → **불러와 7개 탭에 복원**
   - 상단바에 [자료함] 버튼 추가(동기화 버튼 옆)

3. **복제 기능 2종** — 반복입력 절감의 핵심
   - **지점 간 값 복사**: 현재 조사개황만 복사해 *다른 지점* 세션의 시작점 생성.
     연도차수·조사자·날씨·조사기관 유지, **지점명·좌표만 교체**, 종 목록은 비움.
   - **이전 차수 복사 후 수정**: *같은 지점*의 지난 회차를 **종 목록까지 통째로 복제** → 개체수만 갱신.

4. **관리**
   - 세션 삭제(확인 대화상자), 지점·차수 변경(re-key)
   - 내보내기 시 파일명에 세션 정보 자동 반영

## B-4. 반복입력 편의(잔여)

- **Fill-down**: 그리드 선택 셀을 아래로 채우기(Ctrl+D). RadGridView 기본 미지원 → 커스텀 명령.

## 결과 (2026-08-21)

### A. 조사지점 체계

**지점 마스터** `SDSM_Surveyor_App/sites.json` — 제출 엑셀 22개의 `조사지점` 시트에서 생성(`tools/build_sites_json.py`).
버전 `sites-20260821`, **43개 지점**(곡교천 13 · 오산천 20 · 원천리천 10).

> ⚠ 원본 시트의 **열 배치가 하천마다 다르다.** 문서 §A-1 ②의 표(B~I)는 **곡교천에만** 맞는다.
> 오산천은 십진 좌표 + 하천차수 + 연도별 지도번호, 원천리천은 또 다르다. 그래서 변환기는
> **고정 열 인덱스가 아니라 2행 머리글 텍스트로 열을 찾는다.** 시트를 추가·수정해도 재실행하면 된다.
> 생태현황 파일에는 쓸 수 있는 `조사지점` 시트가 없어 현재 생태현황 지점은 0건이다.

**알려진 결측** — 오산천3_1·오산천3_2는 원본에 좌표가 없다(지도 버튼 비활성). St번호가 없는 지점 11곳
(원천리천 전체 + 오산천10)은 지도번호로 대신 찾는다.

- `SDSM_Models/SiteCatalog.cs` — 관리자와 공유하는 `SiteCatalog`·`SurveySite`.
- `Data/SiteListProvider.cs` — `species.json`과 같은 로드 규칙(AppData 교체본 → 실행폴더 번들).
  `Resolve()` 우선순위 **① 지점명 → ② St번호(`ST1`·`St.1`·`st 1`) → ③ 연도별 표기·지도번호**.
- `SurveyOverviewControl` 지점명이 자유입력 → **등록 지점 드롭다운**(편집 가능, ST번호 입력 허용).
  고르면 **하천·사업장·좌표**가 채워지고 `곡교천1 (St.1)`로 병기, 아래에 위치 설명(배방야구장)을 보여준다.
  미등록 값을 치면 지우지 않고 **"미등록 지점입니다"** 경고만 띄운다(오타를 조사자가 알아채도록).
- `Helpers/CoordinateHelper.cs` — DMS(`36°45'47.09"N`) ↔ 십진수 변환, 지도 URL 생성. [지도] 버튼은 좌표가 있을 때만 활성.
- 보고서 엑셀 **14개 시트 전부**의 표 앞머리에 `프로젝트명 | 사업장 | 과업대표하천 | 지점명` 4열 추가(`Export/SiteColumns.cs`).
  조사개황 시트에도 사업장 행을 넣었다. **일괄입력용 엑셀은 관리자 Import 규약이라 손대지 않았다.**

### B. 조사 세션(자료함)

- `Models/SurveySession.cs` — 세션 = `대분류_연도차수_지점`. 공통 조사개황 스냅샷 + 분류군별 상태.
- `Data/SessionStore.cs` — `sessions\{id}.json` + `index.json`. 목록이 깨지면 세션 파일에서 다시 만든다.
- `Data/ITaxonSession.cs` + `ViewModels/Sessions/*.Session.cs` — 7개 분류군이 각자 `CaptureState/RestoreState/ClearData` 구현.
- `Data/SessionService.cs` — 화면 ↔ 세션. 저장·불러오기·삭제·복제 2종·re-key.
- `Views/Windows/SessionBrowserWindow` + `SessionBrowserViewModel` — 자료함 창. 상단바 [자료함] 버튼에서 진입.
- 마이그레이션: 첫 실행 시 `drafts\*.json`을 세션 하나로 편입하고 `drafts\_migrated_to_sessions.txt` 표식을 남긴다(두 번 안 함).

**구조 변경 2가지**(세션 개념상 필요)

1. **조사개황이 진짜로 공유된다.** 전에는 탭마다 `SurveyMeta`가 따로였다(어류 탭에 적은 지점이 조류 탭에 없었다).
   `SurveyMeta`를 DI 싱글턴으로 바꿔 7개 탭이 한 벌을 본다. 7개 분류군 VM도 `ITransientService` → `ISingletonService`.
2. **`ILocalDraftStore`/`LocalDraftStore` 삭제.** 각 탭의 [임시 저장]은 이제 그 분류군만이 아니라
   **세션 전체**를 저장한다. 지점을 옮겨도 이전 지점 자료가 사라지지 않는다.

> `SessionService`는 7개 VM을 **생성자가 아니라 `IServiceProvider`로 늦게** 가져온다.
> 각 VM이 `ISessionService`를 주입받으므로 생성자 주입은 순환 의존이 된다(앱이 시작되지 않는다).
