# A. 조사지점 체계

## A-1. 원천 데이터 (확인 완료)

### ① 관리자 DB `SiteDivision` 테이블 — 4단계 구분
`SiteDivisionId | Project | Workplace | WorkplaceRiver | WorkplaceSite`

| Project | Workplace | WorkplaceRiver | WorkplaceSite |
|---|---|---|---|
| 생태현황 | (null) | (null) | (null) |
| 방류하천 | 기흥 | 오산천 | 오산 |
| 방류하천 | 화성 | 원천리천 | 원천리천 |
| 방류하천 | 온양 | 곡교천 | 곡교천 / 천안천 / 회룡천 |

→ 내보내기 구분 컬럼: **프로젝트명 · 사업장 · 과업대표하천 · 지점명**

### ② 제출 엑셀 템플릿의 `조사지점` 시트 — 지점 마스터
예: `일괄입력자료\2602_방류하천_곡교천_어류_DB_v1.xlsx` → 시트 `조사지점`(행3부터)

| 열 | 내용 | 예 |
|---|---|---|
| B | 지점설명 | 배방야구장 |
| **C** | **DB상 지점명** | **곡교천1** |
| D | 위도(DMS) | 36°45'47.09"N |
| E | 경도(DMS) | 127°5'26.18"E |
| F | 연도별 보고서상 지점명(22~25) | 곡교천-1 |
| G | 연도별 보고서상 지점명(26) | 곡교천1 |
| **H** | **조사장소 번호** | **St.1** |
| I | 비고 | 수질만 |

→ **`ST1 → 곡교천1` 변환의 근거가 H열 ↔ C열이다.**
→ **연도별 지점명 변경 이력**이 F·G열이다(연도 구간별 표기).
→ 비고("수질만")로 **분류군별 적용 여부**를 구분한다.

## A-2. 구현

1. **지점 마스터 파일** `sites.json` 도입
   - 스키마: `{ Version, GeneratedAt, Sites:[{ Project, Workplace, River, SiteName, StNo, Desc, Lat, Lng, YearAliases:{ "22~25":"곡교천-1", "26":"곡교천1" }, Taxa:["수질"] }] }`
   - 로드 규칙은 `species.json`과 동일: `%AppData%\SDSM_Surveyor\sites.json` → 실행폴더 번들
   - 공유 모델은 `SDSM\SDSM_Models\` 에 `SiteCatalog` 로 추가(관리자와 공용)
   - 초기 데이터는 위 엑셀 `조사지점` 시트에서 생성한다(1회 변환).

2. **조사자는 등록된 지점만 선택**
   - `SurveyOverviewControl`의 지점명을 자유입력 → **드롭다운**으로 교체
   - 선택 시 하천명·좌표·사업장이 **자동 채워짐**
   - 대분류(방류하천/생태현황) 선택에 따라 지점 목록이 필터됨

3. **ST 번호 입력 허용 + 자동 변환**
   - 조사자가 `ST1`, `St.1`, `st 1` 로 입력해도 → **`곡교천1`로 정규화**해 저장·내보내기
   - 화면에는 `곡교천1 (St.1)` 처럼 함께 표시해 조사자가 인지하게 한다

4. **좌표 → 외부 지도 연결**
   - 지점 선택 시 좌표 옆 [지도] 버튼 → 기본 브라우저로 지도 열기
   - DMS(`36°45'47.09"N`) ↔ 십진수 변환 유틸 필요(엑셀은 DMS, 관리자 DB는 십진수)

5. **내보내기에 구분 컬럼 추가**
   - 보고서용 엑셀의 출현종·건강성평가 시트 맨 앞에
     `프로젝트명 | 사업장 | 과업대표하천 | 지점명` 추가(현재는 지점명만)

> 관리자 쪽 지점 관리 화면(등록·수정·병합·연도별 이력)은 `..\SDSM\docs\ADMIN_TASKS.md` 참조.

# B. 조사 세션 (자료함)

## B-1. 문제

현재 저장은 `%AppData%\SDSM_Surveyor\drafts\{분류군}.json` **단일 슬롯 덮어쓰기**다.
→ 지점을 바꾸면 이전 지점 자료가 사라지고, 불러오기 화면도 없다. 연 8개 지점을 감당할 수 없다.

## B-2. 개념

**조사 세션** = `대분류 + 연도차수 + 지점` 하나. 이 세션이 **공통 조사개황 + 7개 분류군 데이터**를 함께 보관한다.

## B-3. 구현

1. **저장 구조 개편**
   - `drafts\{분류군}.json` → `sessions\{sessionId}.json` (다건) + `index.json`(목록·메타)
   - `sessionId` = 대분류·연도차수·지점 조합(파일명 안전 문자로 변환)
   - `index.json` 항목: sessionId, 대분류, 연도차수, 지점, 하천, 최종수정일시, 입력된 분류군 목록, 경고 건수
   - **기존 draft 파일이 있으면 1회 마이그레이션**(첫 실행 시 세션 하나로 편입)

2. **자료함 화면**(신규 창 또는 첫 화면)
   - 세션 목록 그리드: 대분류·연도차수·지점·하천·최종수정·입력 분류군·경고
   - 검색·정렬, 행 더블클릭 → **불러와 7개 탭에 복원**
   - 상단바에 [자료함] 버튼 추가(동기화 버튼 옆)

3. **복제 기능 2종** — 반복입력 절감의 핵심
   - **지점 간 값 복사**: 현재 조사개황만 복사해 *다른 지점* 세션의 시작점 생성.
     연도차수·조사자·날씨·조사기관 유지, **지점명·좌표만 교체**, 종 목록은 비움.
   - **이전 차수 복사 후 수정**: *같은 지점*의 지난 회차를 **종 목록까지 통째로 복제** → 개체수만 갱신.

4. **관리**
   - 세션 삭제(확인 대화상자), 지점·차수 변경(re-key)
   - 내보내기 시 파일명에 세션 정보 자동 반영

## B-4. 반복입력 편의(잔여)

- **Fill-down**: 그리드 선택 셀을 아래로 채우기(Ctrl+D). RadGridView 기본 미지원 → 커스텀 명령.
