### ⚠ 최대 난제 — 관찰형 그리드

포유류 22열의 구성:

| 묶음 | 열 | 수 |
|---|---|---:|
| 종 식별 | 일반명 · 학명 · 목 · 과 · 관찰지유형 | 5 |

## 3. 제약 조건 (반드시 지킬 것)

1. **라이선스**: 삼성 로고·브랜드 남색·SamsungOne 서체 **사용 금지**. "삼성 느낌"은 레이아웃·색 운용·절제된 타이포로만 표현한다.
2. **Telerik StyleManager**: `RadTabItem` 등 Telerik 컨트롤에 Style을 통째로 지정하면 테마 템플릿이 벗겨진다. `90_TECH_NOTES.md` §2 참조.
3. **현장 사용성**: 조사자는 야외·노트북 환경에서 **빠르게 많이 입력**한다.
   - 키보드만으로 연속 입력 가능해야 한다(Tab·Enter 흐름)
   - 클릭 수 최소화, 종 입력이 화면의 주인공
4. **정보 위계**: 자동계산 지수(FAI·BMI·등급)는 **입력 결과의 피드백**이지 입력 대상이 아니다. 시각적으로 구분되어야 한다.
5. **경고 표시**: 이상치 경고는 **비차단**. 붉은 강조는 쓰되 작업을 막는 인상을 주지 않는다.
   저장·내보내기를 **막지 않는다**(사용자 지시: "이상치는 알림일 뿐 제제사항이 아니다").

6. 🚫 **입력 항목을 줄이지 않는다.** 사용자의 명시적 지시다.
   > "자동계산 외 모두 입력이 맞다. **단순화는 반복입력을 단순화**"

   화면이 복잡하다는 이유로 필드·그리드 열을 없애거나 접어서 숨기는 설계는 **반려 대상**이다.
   줄여야 할 것은 **같은 값을 여러 번 치는 일**이지 항목 수가 아니다.
   (조사개황 1회 입력 후 접기 · 지점별 값 복사 · 이전 조사자료 복사 후 수정 · 엑셀 붙여넣기가 그 수단이다)

7. 🚫 **내보내기 셀 값이 바뀌면 안 된다.** `docs\_baseline\` 기준 엑셀 20개가 회귀 기준이다.
   디자인 개편은 화면만 바꾼다. VM 속성명·계산·내보내기에 손대면 대조가 깨진다.

8. 🚫 **대분류(Project) 격리를 무너뜨리지 않는다.**
   방류하천과 생태현황에 **같은 이름의 다른 지점**이 있다(`..\..\SDSM\docs\_ecostatus_sites_extracted.md` §8-2).
   - 대분류 선택 전에는 지점 드롭다운이 **비활성**
   - 대분류를 바꾸면 선택된 지점을 **즉시 해제**
   - 지점 목록에 다른 대분류를 **섞어 보여주지 않는다**

   "지점을 먼저 고르게 하면 편하다" 같은 설계는 **불가**다. 자료가 조용히 섞인다.

9. **분류군 3유형을 인정한다.** 하나의 배치로 7개를 다 덮으려 하지 말 것.
   종 입력형(어류·저서) / 관찰형(조류·포유류·양서파충류) / 폼형(수질·서식수변)은
   담을 내용의 성격이 다르다(§2-5). **공통 셸 + 유형별 본문**이 현실적이다.

## 4. Claude Design이 설계할 항목

아래를 이 문서에 **채워 넣는다**(섹션 5로 추가).

> 실측 수치는 §2-5, 지켜야 할 선은 §3에 있다. **§3-6(항목 축소 금지)과 §3-8(대분류 격리)을 먼저 읽을 것.**

1. **레이아웃 원칙** — 그리드 시스템, 여백 스케일, 카드 구획 규칙

2. **화면별 와이어프레임** — 유형별 기준 화면 3개를 먼저
   - **공통 셸**(캡션바 50px · 탭바 · 상태바 · 조사개황 접이식)
   - **종 입력형 — 어류**: 폼 19칸 + 그리드 6열 + 지수 패널. 현재 320px 고정인 지수 패널의 처리
   - **관찰형 — 포유류**: ⚠ **22열**(흔적 12 포함). §2-5의 최대 난제. **열을 줄이지 않고** 담는 방안
   - **폼형 — 수질**: 23칸이 상단 한 줄에 몰려 아래가 비는 현재 문제의 해결
   - 나머지: 저서동물(폼 31칸) · 조류(16열) · 양서파충류(19열) · 서식수변(콤보 15) · 자료함 · 동기화
3. **컴포넌트 스펙** — 폼 필드, 그룹 헤더, 표 헤더, 지수 카드, 등급 뱃지, 경고 표시, 버튼 계층(주요/보조/위험)
   - **종 빠른추가 바**와 **하단 상태·액션 바**는 이 단계에서 UserControl로 새로 설계한다(§6 참조)
4. **토큰 갱신안** — 색·타이포·여백·모서리·그림자 최종값
6. **키보드 흐름** — 종 연속 입력의 Tab·Enter 순서(§3-3). 마우스 없이 한 종을 끝내고 다음 행으로 가는 경로
5. **상태 정의** — 기본/포커스/오류/경고/비활성/읽기전용

### 5-1. 레이아웃 원칙

#### 5-1-1. 성립할 것 / 감수할 것

| | 규칙 |
|---|---|
| ✅ **열 폭이 유지된다** | 1280 폭에서 **선언한 열 폭이 그대로 유지**된다. ⚠ 아래 함정을 볼 것. |
| ✅ 세로 스크롤 허용 | 760 높이에서 폼형·저서동물은 세로 스크롤이 생긴다. **정상이다.** |
| ✅ 조사개황 접힘 | 접었을 때 본문이 최소 **420 px** 확보된다. |
| ⚠ 감수 | 1280에서 그리드 자유폭 열(특징 등)이 **최소폭까지 눌린다**. 텍스트는 말줄임 + 툴팁. |
| ⚠ 감수 | 포유류·양서파충류·조류는 **행 높이가 2단**이 된다(5-2-2). 한 화면 표시 행 수가 절반이 된다. |
| 🚫 금지 | 열·필드 삭제, 탭·아코디언 뒤로 숨기기, "고급" 접기(§3-6) |

> ⚠ **함정 — "가로 스크롤 없음"을 기준으로 삼으면 안 된다 (2026-08-22 실측).**
> `RadGridView` 는 열 폭 합이 뷰포트를 넘어도 **가로 스크롤을 만들지 않는다. 열을 균등하게 뭉갠다.**
>
> ```
> 조류(재배치 전)   1280 폭 :  일반명 선언 190 → 실제  86 px   ← 종명이 안 보인다
> 양서파충류        1280 폭 :  일반명 선언 180 → 실제  70 px
> 포유류(재배치 후) 1280 폭 :  일반명 선언 168 → 실제 168 px   ✅
> ```
>
> 세 경우 모두 "가로 스크롤 없음"은 통과한다. 그래서 검증 기준을
> **`선언 폭 == 실제 폭`** 으로 바꿨다(§7). 뭉개진 그리드는 스크롤이 없을 뿐 못 쓴다.

#### 5-1-2. 8pt 간격 스케일

모든 여백은 아래 6단계만 쓴다. 지금은 2·6·8·10·12·14·16·20·24가 뒤섞여 있다.

| 토큰 | 값 | 용도 |
|---|---:|---|

| `SpaceSm` | 8 | 폼 칸 사이, 버튼 사이 |

#### 5-1-3. 3구획 골격 — 7개 화면 공통

```
[상단] 조사개황 (셸 소유 · 접이식)      ← 7개 탭이 공유. 화면마다 다시 그리지 않는다
[본문] 좌: 주작업 영역   |  우: 결과 레일 (선택)
[하단] 상태 · 액션 바 (셸 소유)
```

**결과 레일 규칙** — 아무 데나 붙이지 않는다.

| 유형 | 레일 | 이유 |
|---|---|---|
| 종 입력형(어류·저서) | **있음** — FAI/BMI 지수 | 결과가 "값"이다 |
| 폼형(수질·서식수변) | **있음** — 등급 요약 / HRI | 결과가 "값"이다. **지금 아래가 비는 문제가 여기서 해결된다** |
| 관찰형(조류·포유류·양서파충류) | **없음** — 하단 상태바로 흡수 | 결과가 총계뿐이다. 레일을 두면 22열이 300 px 더 좁아진다 |

#### 5-1-4. 조사개황을 셸로 올린다 (중요)

### 5-5. 키보드 흐름 (§3-3)

#### 빠른 추가 바 — 마우스 없이 한 종

```
[초성 콤보]  ㄱㄹㄴ  →  ↓/Enter 로 종 선택
      ↓ (자동 포커스 이동 · QuickSpeciesPicked)
[수량]      5        →  Enter
      ↓ (행 추가 후 자동 복귀 · QuickAddCompleted)
[초성 콤보]  ← 다음 종
```

현재 어류·포유류 코드비하인드에 이미 구현돼 있다. **`QuickAddBar`로 추출하면서 5개 화면 전부 같게 만든다.**

#### 그리드 — 한 행을 끝내고 다음 행으로

| 키 | 동작 |
|---|---|
| `Tab` | 다음 칸. 행 마지막 칸에서 → **다음 행 첫 칸**(2단 행이면 2행을 거쳐서) |
| `Shift+Tab` | 역방향 |
| `Enter` | 편집 확정 + **아래 행 같은 칸**(엑셀 습관) |
| `↑ ↓ ← →` | 편집 아닐 때 셀 이동 |
| `F2` | 편집 시작 |
| `Esc` | 편집 취소(값 복원) |
| `Ctrl+V` | 엑셀 다중 행 붙여넣기 — VM이 직접 파싱(§90 TECH_NOTES §2) |
| `Ctrl+Enter` | 새 행 추가 |
| `Alt+1`~`Alt+7` | 분류군 탭 전환 |
| `Alt+S` | 임시 저장 |

**포유류 2단 행의 Tab 순서** (✅ 스파이크로 실측 · 5-2-2)

```
[1행] 일반명 → 학명 → 목 → 과 → 관찰지유형 → (흔적계) → 위도 → 경도 → 특징 → 특이사항 → (구분)
[2행] → 포획 → 관찰 → 울음 → 사체 → 족적 → 털 → 식흔 → 굴 → 번식지 → 배설물 → 카메라 → 기타
      → (다음 행 일반명)
```

괄호는 읽기전용 열이다. **`GridViewDataColumn` 에 `IsTabStop` 이 없어 Tab 순서에서 뺄 수 없다** —
멈추기만 하고 편집은 안 된다. 헛 Tab 2번을 감수한다.

### 5-7. 결정 3가지 — ✅ **전부 승인** (2026-08-22)

| # | 결정 | 권고 | **판정** |
|---|---|---|---|
| 1 | 포유류 22열 — **2단 행** vs **고정 흔적 패드** | 2단 행 | ✅ **2단 행 채택** |
| 2 | 조사개황을 셸로 올리기(5-1-4) | 올린다 | ✅ **올린다** |

**결정 1 — 승인 시 확인된 대가 (기획 측 검산)**

| 안 | 표시 행(1280×760) | 흔적 입력 | Tab |
|---|---:|---|---|
| **2단 행 (채택)** | **6행** | 모든 행의 흔적을 동시에 본다 | ✅ 통과(5-2-2) |
| 고정 패드 (대안) | 9행 | 선택한 행만 | 완전 통제 |

사용자가 6행을 알고 2단 행을 택했다. **표시 행이 줄어드는 것은 승인된 대가다** — 구현 중에
"행이 적게 보인다"는 이유로 흔적 열을 접거나 숨기는 쪽으로 되돌아가지 말 것(§3-6 위반).

> ⚠ **스파이크가 실패하면 고정 흔적 패드로 자동 전환한다.** 사용자에게 다시 묻지 않는다.
> 두 안 모두 22열을 줄이지 않고 1280에서 가로 스크롤이 없으므로, 어느 쪽이든 승인 범위 안이다.
> 다만 **전환했다면 반드시 보고할 것**(표시 행이 6 → 9로 늘고 흔적 동시 비교가 사라진다).

## 6. 구현 지침 (Claude Code)

- 스펙 확정 후 `Styles\Colors.xaml`·`Styles\Styles.xaml`을 **먼저** 갱신하고, 화면은 그 토큰만 참조하게 한다. 화면에 색·수치를 직접 쓰지 않는다.
- **유형별로 기준 화면 하나씩** 완성해 승인받은 뒤 같은 유형에 복제한다.
  종 입력형 → **어류**, 관찰형 → **포유류**(22열, 가장 어려움), 폼형 → **수질**.
- 공통 컨트롤 현황 — **`SurveyOverviewControl` 하나만 추출돼 있다.**
  빠른추가 바·상태바는 5단계 R6에서 **일부러 추출하지 않았다**(디자인이 바뀌면 다시 뜯을 것이라).
  → **UserControl 설계는 이 단계의 일이다.** §5 스펙이 정한 구조대로 새로 만든다.
- 아이콘 Kind는 사용 전 DLL에서 존재를 확인한다(`90_TECH_NOTES.md` §0).
- ⚠ **XAML 바인딩 이름을 바꾸지 않는다.** VM 속성명(`SpeciesEntries`·`Entries` 등)은 5단계에서
  파생 클래스가 기반의 `Rows` 를 그 이름으로 노출하도록 맞춰 둔 것이다. 바꾸면 기준 파일 대조가 깨진다.
