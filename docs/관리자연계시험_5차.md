- UI 하네스는 채팅으로 알린 뒤, **PC 입력이 2분 없을 때** 단계마다 돌렸다. 단계당 실행 한도 **10분**(`quiet_run.ps1 -RunMaxMin 10` — 넘으면 그 프로세스의 보이는 창(클래스 · 제목)을 적고 끝냄). **한도를 넘은 단계는 없었다**(가장 긴 단계 boundary 6분 20초 · final_input 5분 30초 · 1차 등록 4분 50초).

- 재현: 조사자 저서 탭 → 조사환경 펼침 → 수온 칸에 `18.3Z`(또는 평균수심 `0ㅓ.3`) → [일괄입력용] → 관리자 일괄등록 [엑셀자료 가져오기] → '오류 1' · `[수온]형변환실패` · [변환된 자료 일괄 저장] 비활성. 1번째 시도에서 실제로 일어났다(시험 중 사용자 키 입력이 섞임 · `등록\reg_p1\run.log` 앞부분 · 시험 DB `SDSMDB_test_5th_try1.sqlite`).
- 원인: 이 여섯 칸은 `RadWatermarkTextBox` 에 문자열로 묶여 있고(`BenthosEntryControl.xaml`) 정수 칸의 `IntegerInput` 같은 입력 막기 · 경고가 없다. 저서 [일괄입력용]에는 어류의 `BulkBlockReason` 같은 확인도 없다. 관리자는 `double` 변환 실패를 오류로 본다(지금처럼 맞는 동작).
- 영향: 현장에서 오타가 나면 파일은 만들어지지만 관리자 등록에서 그 기록 전체가 막혀, 조사자 쪽으로 되돌아가 고쳐야 한다. 지수 계산에는 영향 없음(환경값은 지수에 안 들어감).
- 고칠 방법(제안): 소수 칸에 숫자 · 소수점만 받는 입력 동작(정수 칸 `IntegerInput` 의 소수판) 또는 숫자가 아니면 칸 경고 + [일괄입력용] 막힘 · 안내. 수질 탭 소수 칸도 같은 방식인지 함께 본다(이번에 수질은 보지 않음).

**2. 관리자 [종목록 내보내기] 알림이 조사자 v0.5.0 동작과 다르다(문구)**
