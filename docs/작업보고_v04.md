## 1. 바뀐 것

### 1-1. N1 — 클립보드 · 앱 전역 예외

**클립보드** — `Clipboard.` 를 읽는 곳 3곳(`ObservationGrid` · `FishEntryControl` · `BenthosEntryControl` 의 Ctrl+V)을 `ClipboardText.TryRead` 하나로 모았다.
- 5회 × 50ms 다시 시도 → 그래도 못 읽으면 토스트 '클립보드를 읽지 못했습니다 — 잠시 뒤 다시 붙여넣으세요'. 입력은 그대로.
- ⚠ 시험에서 찾은 것: WPF 클립보드는 잡혀 있으면 **안에서 약 1초** 다시 시도한 뒤 실패한다 → 5회면 화면이 약 5초 멈춘다.
  그래서 시도마다 먼저 Win32 `OpenClipboard(우리 창)` 로 열어 보고(바로 실패) 잡혀 있으면 곧장 다음 시도로 넘긴다 — 시험에서 잡힌 상태 Ctrl+V 처리 **244ms**.
  창 없이(NULL) 열면 다른 프로그램이 NULL 로 연 것과 겹쳐도 성공하고 닫을 때 그 프로그램의 열기까지 닫아 버린다(시험에서 확인) — 반드시 우리 창 핸들로 연다.

**전역 예외** — `Data\CrashGuard`(ISingletonService) · `App.OnStartup` 첫 줄에서 설치.
- `DispatcherUnhandledException`(처리함으로 표시 — 앱을 닫지 않음) · `AppDomain.UnhandledException` · `TaskScheduler.UnobservedTaskException`(관찰 처리).
- ① 자료함 `logs\error_yyMMdd.log` 에 시각 · 어디(화면/백그라운드/비동기 작업) · 판(0.4.0+커밋) · 예외 전문.
- ② 분류군 자료가 있으면 `SessionService.CaptureCurrentSession()`(저장과 같은 세션 형식 · 분류군 조사일 포함)을 `_recovery\{세션키}_{yyMMdd_HHmmss}.json` 에. **정식 세션 파일·목록(index.json)은 건드리지 않는다.** 화면 VM 은 UI 스레드에서만 읽는다(백그라운드면 UI 스레드에 맡기고 5초 안에 시작 못 하면 포기).
- ③ 안내 창: 오류 기록 위치 · 임시 저장 위치(없으면 '입력한 분류군 자료가 없어 임시 저장은 하지 않았습니다') · '계속 쓰기 전에 [임시 저장]'. 처리 중 또 예외가 오면 기록만(무한 반복 방지).
- 다음 실행: 창이 뜬 뒤(구판 편입·예시 시드 다음) `_recovery` 에 파일이 있으면 '복구본이 있습니다 — [불러오기]/[나중에]'(가장 최근 것 · 개수 표시).
  [불러오기] = `ApplyRecovered` — 화면에 올리기만 하고 새 세션(같은 키가 있으면 저장 때 [합치기/바꾸기/취소]) · '저장 안 한 변경' 상태 · 그 복구본은 `_recovery\loaded\` 로 옮김(지우지 않음). [나중에] = 그대로(다음 실행에 또 묻는다).
- 경로는 모두 `ISessionStore`(`Location` · `AppendErrorLog` · `SaveRecovery` · `ListRecovery` · `LoadRecovery` · `SetRecoveryAside`)를 거친다 — 하네스 가짜 자료함은 메모리에만 쓴다.

### 1-2. N2 — 정수 칸

`Behaviors\IntegerInput`(개체수·하상 %·채집시간·DE~TU 등 정수 칸 25곳이 쓰는 것) — 종전에는 글자 단위로 '.' 만 막혀 '1.5' → '15'.
- 숫자가 아닌 글자(소수점·쉼표·문자·공백)를 치면 ① 받지 않고 ② 칸을 **이 칸에 들어왔을 때의 값**으로 되돌리고 ③ 칸 아래에 '정수만 넣습니다 — 소수점·글자는 받지 않습니다' 를 2.5초.
  안내가 떠 있는 동안은 이어 치는 숫자도 받지 않는다 — '1.5' 를 빠르게 쳐도 '15'·'1' 이 남지 않는다.
  지우기·이동·확정 키 · Ctrl 조합(Ctrl+A) · 칸 누르기 · 칸 떠나기로 바로 풀린다(안내를 본 뒤 고치는 동작은 막지 않는다).
- 범위를 넘으면(하상 % 101 등) 받지 않고 '0~100 사이 정수만 넣습니다'.
- 붙여넣기: 정수가 아니면 통째로 받지 않고 같은 안내(종전에도 막았지만 안내가 없었다).
- 그리드 여러 칸 붙여넣기(`SpeciesEntryViewModelBase.PasteInt` — 어류 개체수 · 조류 개체수 · 포유류 흔적 12칸 · 양서 흔적 6칸): 정수가 아닌 칸은 넣지 않고(행은 넣음) 끝에 한 번
  'n칸은 정수가 아니라 넣지 않았습니다(1행 6열 '1.5' · 2행 6열 '약간')'(칩 + 토스트 · 6칸 넘으면 '외 n칸'). 저서 개체수는 소수 허용이라 그대로.

### 1-3. N3 — 분류군별 조사일

- **칸**: `TaxonEntryViewModelBase.TaxonSurveyDate`(7개 분류군 공통) · `EffectiveSurveyDate = TaxonSurveyDate ?? 조사개황 조사일`.
  화면은 `Views\UserControls\TaxonDateBar` — 어류·저서·수질·서식수변은 탭 맨 위 한 줄(안내 글자 함께), 조류·포유류·양서는 요약줄 오른쪽(안내는 툴팁 · 좁은 줄).
  비었을 때 칸에 '2025-10-01 (조사개황)' 이 흐리게 보인다. 조사개황 날짜를 바꾸면 빈 분류군은 따라간다.
  (기존 조사일 검사 규칙은 없었다 — 조사개황 조사일에도 검사가 없어 같은 규칙 = 없음)
- **내보내기**: 일괄입력용 7개 · 보고서 7개의 조사일(행 · 건강성평가 표 · 조사개황 '조사일자')이 모두 `vm.EffectiveSurveyDate`. `ReportExporterBase.WriteSurveyMeta` 에 조사일 인자를 더했다.
- **세션 파일**: 분류군 자료 JSON 안에 `TaxonSurveyDate` 칸 하나(있을 때만). 넣고 빼는 곳은 `SessionService.Capture/Restore/Clear` 한 곳 — 분류군 DTO(FishDraft 등)는 그대로.
  어류·저서 DTO 에는 예전부터 조사개황 사본 `SurveyDate` 가 있어 이름을 달리 했다. 칸이 없는 예전 세션 = 분류군 조사일 없음(조사개황을 따름). 세션 키·파일 이름 규칙 무변경.
- **합치기**: 그대로 둘 기존 분류군의 실제 조사일(분류군 칸 또는 기존 조사개황)이 새 조사개황 조사일과 다르면 그 분류군 자료에 옮겨 적는다.
  확인 창에 '합치면: 포유류 조사일 2025-09-06 유지 / 조사일자 · 2025-09-06 → 2025-10-01 / 조사자 · 김OO → 이OO'(값이 바뀌는 조사개황 칸 전 → 후) — 사진 `dialog_같은_자료가_이미_있습니다.png`. 저장 뒤 알림에도 같은 글.
- [차수 복제]는 지난 차수의 분류군 조사일을 비운다(새 차수 조사개황 조사일을 따름). [새 지점]·[지점 복사]·불러오기도 분류군 조사일을 비우고 다시 채운다.
- 저장 안 한 변경(B-5) 판정에 분류군 조사일도 들어간다.

### 1-4. N4 — 하천명

- 하천명 칸은 원래 고칠 수 있었지만 **세션을 다시 열면 지점 목록 하천으로 덮였다**(`SurveyMetaSnapshot.ApplyTo` 가 마스터에 하천이 있으면 저장값을 버림). 저장된 하천명이 있으면 그것을 쓰게 고쳤다.

## 3. 확인 부탁

1. 조사일 칸 위치 — 어류·저서·수질·서식수변은 탭 맨 위 한 줄, 관찰형은 요약줄 오른쪽(사진 `v04_01~03`). 다른 자리가 낫다면 알려 주세요.
2. 정수 칸 — 숫자가 아닌 글자를 치면 **그 칸에 들어왔을 때 값**으로 되돌린다('3' 에서 '31.' 까지 치면 '3'). 안내가 떠 있는 2.5초 동안은 이어 치는 숫자도 막는다(지우기·Tab·칸 누르기로 바로 풀림).
3. 복구본 — 오류가 났지만 앱이 계속 돌아 조사자가 [임시 저장]까지 했어도, 다음 실행에 복구본을 한 번 묻는다([나중에]면 계속 묻고, [불러오기]면 `loaded` 로 옮겨 다시 묻지 않음). 정식 저장 뒤 복구본을 자동으로 치우지는 않았다(자료를 지우지 않는 쪽).
4. 관리자 쪽(§18 N4·N5·문제 4)은 관리자 저장소 몫이라 손대지 않았다. 3차 연계 시험 때 함께 본다.
5. 작업 중 지시서에 §19(관리자 N4·N5 확인 사항, 07:43)가 더해졌다 — 이 작업에서 고치지 않았고 커밋 대상에 섞여 있으니 함께 커밋할지 정해 주세요.
   §19-5 의 '조사자 앱은 정수만 냄' 은 저서 개체수에는 맞지 않는다 — 조사자 저서 개체수 칸은 소수를 받고(종전 그대로 · N2 대상 아님) 일괄입력용에도 그대로 나간다
   (경계 사례 B05 '물벌레류(연갑강)' **2.5** → `docs\_screens_v04\내보낸파일\boundary\B05\` 저서 일괄입력용 M170 = 2.5).
