# 회귀 기준 엑셀 (`docs\_baseline\`)

> `05_REFACTORING.md` §0-2 · R0 에서 만든 **리팩토링 전 기준선**이다.
> 리팩토링은 "동작이 같은가" 하나로 판정한다. 이 폴더가 그 판정 근거다.

## 무엇인가

`tools\BaselineGen\` 의 **고정 픽스처**로 7개 분류군을 채우고 14개 exporter 를 직접 호출해 만든 엑셀이다.
화면에서 손으로 넣은 값이 아니므로 **누가 언제 돌려도 같은 파일**이 나온다.

| 파일 | 내용 |
|---|---|
| `*_report.xlsx` (7) | 보고서용 — 조사개황 · 출현종 · 건강성평가 |
| `*_bulk.xlsx` (7) | 일괄입력용 — 관리자 Import 양식 |
| `fish_m8_*.xlsx` (2) | 비정상종 비율 **10%** — M8 상단 구간(`>1% → 0점`) |
| `fish_zero_*.xlsx` (2) | 0종(빈 조사) — **점수 0 · 등급 E** |
| `habitat_zero_*.xlsx` (2) | 서식수변 평가항목 10개 **전부 0점** — 합계 0 · **점수 0 · 등급 E** |

## 무엇을 지키는가

| 회귀 위험 | 잡아 주는 케이스 |
|---|---|
| M8 정수 나눗셈 부활 (`12_CALC_FIX` §1) | 본 케이스 **0.1% → 6.25점**, M8 케이스 **10% → 0점**. 정수 나눗셈이면 둘 다 12.5점이 되어 즉시 어긋난다 |
| 0종 판정이 `37.5·D` 로 되돌아감 | `fish_zero_*` → `0 · E` |
| `null`(미조사)과 `0`(실측 부재) 혼동 | 분류군마다 두 값을 섞어 넣었다 |
| 이상치 경고 로직 변화 | 어류 `밀어 9999`, 저서동물 `실지렁이 5000` |
| 대분류 격리 (`_ecostatus` §8-2) | 픽스처가 `방류하천 / St.1` 로 지점을 해석한다 |
| 좌·우안 한쪽만 입력한 HRI 항목 | 서식수변 `B6R` 만 비움 |
| HRI 판정 기준이 `total != 0` 으로 되돌아감 (`_excel_formula_audit` §5) | `habitat_zero_*` → `0 · E`. 합계로 판정하면 10개를 전부 0점으로 고른 조사가 미평가(`-`)로 빠진다 |

## 쓰는 법

```
# ① 리팩토링 후 현재 코드로 다시 뽑는다 (저장소 밖으로)
dotnet run --project tools\BaselineGen\BaselineGen.csproj -- --out C:\Temp\after

# ② 셀 단위로 대조한다
python tools\baseline_diff.py docs\_baseline C:\Temp\after
```

`===== 셀 값 전부 일치 =====` 가 나와야 그 단계를 통과한 것이다.
차이가 나오면 **그 단계만 되돌린다**(`05_REFACTORING.md` §2-C).

> xlsx 는 zip 안에 생성 시각이 들어가 바이트 비교가 불가능하다. 그래서 **셀 값**만 본다.
> `BaselineGen` 은 `Telerik.Licensing` 증빙을 갖고 있어 `License` 시트 없이 만든다(2026-10-17).
> 증빙 없이 만든 파일에 붙는 `License` 시트는 대조 도구가 여전히 비교에서 뺀다.

## 손대면 안 되는 것

- **픽스처 값을 바꾸지 않는다.** 바꾸면 기준선이 통째로 달라져 이전 단계와의 비교가 끊긴다.
  케이스를 늘려야 하면 **기존 값은 두고 새 케이스를 추가**한다.
- 픽스처에 난수·`DateTime.Now`·`DateTime.Today` 를 쓰지 않는다. 조사일은 `Fixtures.SurveyDate` 고정값이다.
- `BaselineGen` 은 `%AppData%\SDSM_Surveyor\` 를 **읽지도 쓰지도 않는다**(§0-3).
  운영 제공자 대신 저장소 번들만 읽는 `RepoProviders.cs` 를 쓴다. 이 구조를 바꾸지 말 것.
