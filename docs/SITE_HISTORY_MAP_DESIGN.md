## 1. 왜 필요한가

### 1-1. 이름 문제
**오산천은 시기마다 지점 번호를 다시 매겼고 DB에도 그 시기 이름이 그대로 들어 있어서, 지점명만으로 연도를 잇는 순간 다른 장소가 한 줄에 섞인다.**

| 물리 지점 | 2011~12 | 2014~16 | 2018~21 | 2022~25 | 2026 |
|---|---|---|---|---|---|
| 용인하수처리수 유입 | 오산천2 | **오산천3** | **오산천3** | 오산천2 | 오산천2 (st2) |
| 삼성 방류수 | 오산천3 | **오산천5** | **오산천5** | 오산천3 | 오산천3 (st3) |
| 석우보 | 오산천4 | 오산천6 | 오산천7 | 오산천5 | 오산천5 (st4) |

곡교천·원천리천은 **DB 이름이 바뀐 적이 없다.** 바뀐 것은 보고서 표기뿐이다(`곡교천-1`↔`곡교천1`, `WC-1`↔`원천리천1`).
따라서 이력 관리가 실제로 필요한 것은 **오산천 하나**다.

### 1-2. 좌표 문제 — 이쪽이 더 급하다
같은 지점인데 해마다 좌표가 다른 자료가 **40건** 있다. 최대 17 km.

| 분류군 | 지점 | 연도 | 편차 | 정황 |
|---|---|---|---|---|
| 어류 | 오산천5 | 2023 | 11.5 km | 다른 해와 완전히 다른 위치 |
| 어류 | 오산천4 | 2023 | 10.1 km | 그 해에만 나타나는 지점 |
| 어류 | 오산천3 | 2025 | 4.3 km | 경도 `127.137778` — `127.088778` 오타로 보임 |
| 어류 | 오산천1 | 2023·2025 | 3.6 km | 2022·2024는 정상 |
| 어류 | 오산천2 | 2025 | 4.0 km | 좌표가 오산천6(금반교) 위치 |

**입력하는 순간 알려줬으면 한 건도 안 남았을 것들이다.** 그래서 §3이 이 문서의 1순위다.

## 2. 지점 간격 — 임계값을 정하는 근거

등록 지점 41곳의 "가장 가까운 이웃까지 거리"를 계산했다.

| | 거리 |
|---|---|
| 최소 | **76 m** — 원천리천1(원천천 상류) ↔ 원천리천2(방류구) |
| 25% 분위 | 240 m |
| 중앙값 | 456 m |

가까운 순 상위:

| 거리 | 지점 | ↔ | 지점 |
|---|---|---|---|
| 76 m | 원천리천1 원천천 상류 | ↔ | 원천리천2 방류구 |
| 157 m | 오산천4_5 치동천 하류 | ↔ | 오산천5 석우교·청계교 |
| 168 m | 북수리1 방류구 상류 | ↔ | 북수리2 방류구 하류 |
| 212 m | 오산천4 석우보 | ↔ | 오산천4_1 석우보 300 m 하류 |
| 240 m | 오산천2 용인하수처리수 | ↔ | 오산천3 삼성 방류수 |

**고정 거리 임계값은 쓸 수 없다.** 200 m로 잡으면 원천리천1↔2 혼동을 못 잡고, 100 m로 잡으면 정상 입력이 계속 걸린다.
→ **상대 판정**을 쓴다(§3-1).

## 3. ★ 좌표 검증 경고 (최우선)

### 3-1. 판정 규칙

지점명이 선택되어 있고 위도·경도가 둘 다 읽히면 판정한다.

```
1) 범위 검사    위도 33~39 · 경도 124~132 밖  →  [빨강] 좌표를 다시 확인하세요
2) 최근접 검사  입력 좌표에서 가장 가까운 등록 지점을 찾는다
                그것이 선택한 지점이 아니면      →  [빨강] + 그 지점 이름을 알려준다
3) 반경 검사    선택한 지점까지 거리 > 허용반경  →  [노랑]
4) 그 외                                        →  [회색] 등록 좌표에서 N m
```

**허용 반경은 지점마다 자동 계산한다.**
```
허용반경 = clamp( 그 지점에서 가장 가까운 이웃까지 거리 × 0.45,  30 m,  150 m )
```
| 지점 | 이웃까지 | 허용반경 |
|---|---|---|
| 원천리천1 | 76 m | 34 m |
| 오산천4 석우보 | 212 m | 95 m |
| 오산천1 농서교 | 240 m | 108 m |
| 대부분의 지점 | 456 m 이상 | 150 m (상한) |

- 사람이 숫자를 조정할 필요가 없다. 지점이 추가·이동되면 반경이 저절로 따라간다.
- 마스터에 좌표가 없는 지점은 **판정하지 않는다.** (없는 것을 틀렸다고 하지 않는다)

### 3-2. 화면 — 조사자앱

기존 **이상치 경고**와 같은 방식이다. **비차단** — 저장·내보내기를 막지 않는다.
(`FishEntryViewModel.WarningCount` / `TaxonStatusBar.WarningText` 패턴을 그대로 쓴다)

좌표 칸 바로 아래 한 줄:

```
 위도  [ 37.185148        ]   경도  [ 127.083347       ]   [지도]
 ⚠ 이 좌표는 오산천6(금반교 아래)에 더 가깝습니다 — 오산천2에서 4.0 km
   [ 오산천6으로 바꾸기 ]  [ 등록 좌표로 되돌리기 ]
```

| 판정 | 문구 | 색 |
|---|---|---|
| 범위 밖 | `⚠ 좌표를 다시 확인하세요 (위도 33~39 · 경도 124~132)` | 빨강 |
| 다른 지점이 더 가까움 | `⚠ 이 좌표는 {가까운지점}({설명})에 더 가깝습니다 — {선택지점}에서 {거리}` | 빨강 |
| 반경 초과 | `⚠ 등록 좌표에서 {거리} 떨어져 있습니다` | 노랑 |
| 정상 | `등록 좌표에서 {거리}` | 회색 |

- 빨강일 때만 버튼 2개를 띄운다. `[{가까운지점}으로 바꾸기]` 는 지점명을 바꾸고 나머지 개황(하천명·사업장·대권역)도 함께 갱신한다.
- 상태바 `⚠ 이상치 경고 N건` 에 합산한다.
- **좌표를 자동으로 고치지 않는다.** 조사자가 실제로 그 자리에서 잰 값일 수 있다.

### 3-3. 화면 — 관리자앱

1. **직접 입력 화면**: 조사자앱과 같은 판정, 같은 문구.
2. **일괄등록 미리보기**: 좌표 판정 열을 추가한다. 빨강 행은 기본으로 체크 해제하고, 사람이 다시 켤 수 있게 한다.
3. **[설정 → 좌표 점검]** (신규 배치 기능)
   - 전 DB(7개 테이블)를 훑어 §3-1 판정을 돌린다
   - 결과: `분류군 · 연도차수 · River · Site · 입력좌표 · 등록좌표 · 거리 · 판정 · 가장 가까운 지점`
   - 엑셀로 내보내기 / 행 더블클릭 → 그 자료로 이동
   - **현재 게시 DB로 돌리면 40건 이상이 나온다.** `조사지점_정리_260909.xlsx [좌표이상]` 과 대조해 검증한다.

### 3-4. 이름이 바뀐 시기의 좌표 판정
과거 자료를 점검할 때는 **그 해 이름 → SiteId → 마스터 좌표** 순으로 푼다(§4-3 `site_names.json`).
이름 이력이 없는 자료는 판정하지 않고 `이력 없음` 으로 남긴다. 틀린 기준으로 경고하면 신뢰를 잃는다.

### 3-5. 맹점

| # | 무엇이 터지나 | 막는 법 |
|---|---|---|
| C1 ●●● | **경고가 잦으면 조사자가 무시한다.** 원천리천1의 허용반경 34 m는 GPS 오차(수 m~수십 m)와 겹칠 수 있다 | 하한 30 m 는 그래서 둔 것이다. 실제 운용에서 오탐이 잦으면 하한을 50 m 로 올린다. **판정 결과를 로그로 남겨 오탐률을 볼 수 있게 한다** |
| C2 ●●● | **좌표를 자동 보정하면 진짜 이동을 덮어쓴다.** 하천 공사로 지점이 실제로 옮겨가는 일이 있다 | 자동 보정 금지. 사람이 [되돌리기]를 눌러야만 바뀐다 |
| C3 ●● | **도분초·십진수가 섞여 들어온다** (`37°13'14.86"` / `37.185467`) | 기존 `Coordinate.ToDecimal` 로 통일. 못 읽으면 판정을 건너뛰고 `좌표 형식을 읽을 수 없습니다` |
| C4 ●● | **위도·경도를 바꿔 넣으면** (127.08, 37.18) 범위 검사에 걸린다. 하지만 `127.0, 37.1` 같은 값은 위도 127이 범위 밖이라 잡힌다 | 범위 검사에서 "위도·경도가 바뀐 것 같습니다" 를 별도 문구로 안내한다 |
| C5 ●● | **조류·포유류는 구간 단위**라 좌표가 넓게 흩어지는 것이 정상이다 | 구간 레코드에는 `RadiusOverride` 를 두고 판정에서 제외하거나 반경을 크게 준다 |
| C6 ● | **생태현황은 등록 지점이 아직 없다** | 마스터에 없으면 판정하지 않는다 |
| C7 ● | 위·경도 중 하나만 고치는 중간 상태에서 경고가 깜빡인다 | 두 값이 모두 유효할 때만 판정. 입력 후 300 ms 디바운스 |

## 4. 데이터 구조

두 앱이 **같은 폴더 구조**를 읽는다. 양쪽 모두 편집할 수 있다.

```
<앱폴더>\sitedata\
    sites.json          물리 지점 마스터   ← 기존 sites.json 확장
    site_names.json     지점명 이력(별칭)  ← 신규
    maps.json           지도 카탈로그      ← 신규
    maps\*.png
```

### 4-1. `sites.json` — 물리 지점 (기존 `SurveySite` 확장)
```json
{ "SiteId":"REL-0003", "Project":"방류하천", "Workplace":"기흥",
  "WorkplaceRiver":"오산천", "River":"오산천",
  "SiteName":"오산천3",                  // 2026 기준 현재 이름 (앱 식별자)
  "Description":"삼성 방류수",
  "Lat":37.219075, "Lng":127.088778,
  "RiverChasu":2,
  "MapLabel":"st3",                      // 2026 공통지도 라벨
  "RadiusOverride":null,                 // m. 지정하면 §3-1 자동 반경 대신 이 값을 쓴다
  "ValidFrom":null, "ValidTo":null,
  "Taxa":["수질","어류","저서동물","서식수변"],
  "Photos":[] }
```
- `SiteName` 은 **2026 기준 현재 이름**으로 통일한다. 과거 이름은 전부 `site_names.json` 으로 뺀다.
- `Taxa` 가 비면 전 분류군. 조류·포유류 구간은 별도 레코드로 만들고 `Taxa:["조류"]` 로 격리한다.

### 4-2. `maps.json` — 지도 카탈로그
```json
{ "MapId":"osan_common_26",
  "Project":"방류하천", "River":"오산천",
  "Taxon":"*",                        // "*" = 전 분류군 공통
  "FromYear":2026, "ToYear":null,
  "File":"maps/오산천_공통_26.png",
  "Width":1040, "Height":548,
  "IsLatest":true,                    // 조사자앱이 기본으로 여는 지도
  "Variant":null,                     // "상류" | "하류" | "지점번호안A" 등
  "Calibration":{ "x":[a,b,c], "y":[a,b,c] },   // px = a*lon + b*lat + c
  "Bounds":{ "lonMin":..,"lonMax":..,"latMin":..,"latMax":.. },
  "Source":"기본탑재",                 // 기본탑재 | 사용자추가
  "Note":"" }
```
- **`IsLatest` 는 (Project, River) 당 하나.** 조사자앱이 기본으로 여는 지도다.
- 보정이 없으면 `Calibration: null` — 그림만 보여주고 마커를 찍지 않는다.
- `Source` 는 정보 표시용이다. **잠그거나 막는 데 쓰지 않는다.**

### 4-3. `site_names.json` — 지점명 이력
```json
{ "SiteId":"REL-0003", "Taxon":"수질",
  "FromYear":2014, "ToYear":2016,
  "River":"오산천",          // 그 시기 DB의 River 값
  "Name":"오산천5",          // 그 시기 DB의 Site 값
  "MapNo":"2",               // 그 시기 지도에 인쇄된 번호
  "Source":"DB확인" }        // DB확인 | 시트 | 추정
```
- `(Taxon, FromYear~ToYear, River, Name)` 이 **DB 조회 키**다.
- 같은 SiteId 의 구간은 겹치지 않는다. 겹치면 로드 시 오류.
- `Taxon: "*"` 이면 전 분류군 공통(곡교천·원천리천).
- `Source`
  - `DB확인` — DB 실데이터와 좌표로 확인됨. **계산·조회에는 이것만 쓴다.**
  - `시트` — 조사지점.xlsx 에만 있고 DB에 대응 자료가 없음. 화면에 회색 표시.
  - `추정` — 사람이 판단해 넣음. 물음표 표시.
- 보고서 표기 별칭(`곡교천-1`, `WC-1`)도 여기 넣되 `MapNo` 는 비운다.

## 5. 화면 설계

### 5-1. 지도 관리 — 양쪽 앱 공통

**조사자앱 [설정 → 지도]** 와 **관리자앱 [설정 → 지점·지도 관리 → 지도 탭]** 은 **같은 화면, 같은 권한**이다.

```
 권역     분류군   기간        Variant   파일                      보정  최신  출처
 오산천   공통     2026~       -         오산천_공통_26.png         ○    ●    기본탑재
 오산천   수질     2011~2013   상류      오산천_수질_11-13_상류.png  ×         기본탑재
 오산천   수질     2022~2025   번호안B   내가받은지도.png            ○         사용자추가
                       [＋추가] [교체] [보정] [최신으로 지정] [삭제] [내보내기] [가져오기]
```
- 추가·교체·보정·삭제·순서 변경 **전부 자유**. 승인·잠금·확정 게이트 **없음**.
- [내보내기] → `maps_YYYYMMDD.zip` (maps.json + png). [가져오기] → 그대로 반영.
  메일로 주고받는 통로일 뿐이고, 강제하지 않는다.
- **남기는 안전장치는 딱 둘** — 정확성 문제라서 남긴다.
  1. 교체한 이미지의 가로·세로 픽셀이 다르면 **보정을 무효화하고 재보정을 요구**한다. (안 그러면 마커가 엉뚱한 데 찍힌다)
  2. 2점 보정 시 두 점 사이 픽셀 거리가 대각선의 30% 미만이면 경고한다. (오차가 크게 벌어진다)

### 5-2. 조사자앱 · 지도 팝업

```
┌ 지도 · 오산천 (2026 공통) ──────────────── [과거 지도 ▾] [지도 관리] [닫기] ┐
│                                                                            │
│              ● 오산천3 (37.219075, 127.088778)                             │
│              지도에 인쇄된 라벨: st3                                        │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
```
- 기본은 `IsLatest` 지도 한 장. 마커는 **현재 입력된 좌표 하나**만.
- `[과거 지도 ▾]` — 그 권역의 과거 지도. 고르면 `참고용 · 2011~2013 수질(상류)` 띠가 뜬다. 보정이 있는 지도에서만 마커를 찍는다.
- 지도가 없는 권역(생태현황·기흥·화성 일부)은 `이 권역은 지도가 아직 없습니다. [지도 관리]에서 추가할 수 있습니다.`
- **§3의 좌표 경고가 떠 있으면 팝업 상단에도 같은 문구를 띄운다.** 지도에서 눈으로 확인하는 것이 가장 빠르다.

### 5-3. 조사자앱 · 지점 검색에 과거 이름 포함
조사자에게 이력 화면은 필요 없다. 다만 예전 보고서를 보고 `오산천5` 를 찾으면
`오산천3 (삼성 방류수) · 이전 이름 오산천5` 로 나오게 한다.

### 5-4. 관리자앱 · 설정 → 지점·지도 관리

탭 4개.

**① 지점** — 물리 지점 마스터

```
[대분류 ▾ 방류하천] [권역 ▾ 오산천] [분류군 ▾ 전체]     [＋추가] [엑셀] [일괄변경] [좌표 점검]
──────────────────────────────────────────────────────────────────
 SiteId     현재 이름   지점설명            위도       경도       차수  지도라벨  허용반경
 REL-0001   오산천1     농서교 하류         37.222822  127.093178   2    st1     108 m

```

- 허용반경은 §3-1로 자동 계산해 보여준다(읽기 전용, `RadiusOverride` 로만 덮어쓴다).

**② 이름 이력** — `site_names.json` 편집

- 겹치는 기간 · 빈 구간 · 미매칭 Site 를 위쪽 경고 목록에.

### 5-5. 변천 열람 화면

```
[분류군 ▾ 저서동물]  [권역 ▾ 오산천]     2013 ──────●───────────── 2026   ◀ ▶
─────────────────────────────────────────────┬────────────────────────────
 현재 이름   2015년 이름   지도번호   자료      │  [ 오산천_저서동물_15-21 ]
 오산천1     -            -          없음 ▨   │
 오산천2     오산천2       2          2건      │      ● 선택 지점만 표시
 오산천3     오산천1       1          2건      │
 오산천5     -            -          없음 ▨   │      (보정 없는 지도는
─────────────────────────────────────────────┤       그림만 표시)
 선택: 삼성 방류수 · REL-0003 · 37.219075, 127.088778
 이름 변천 ├2013~14 오산천3┤├2015~21 오산천1┤├2022~26 오산천3┤
 자료      2013·14·15·…·25년  총 26건                    [연도별 자료 보기]
```
- **첫 열은 언제나 현재 이름.** 그 해 이름은 두 번째 열에 따로. 이게 이 화면의 전부다.
- 그 해 조사하지 않은 지점은 회색 + `없음`. 목록에서 빼지 않는다 — "그 해 빠졌다"가 정보다.
- 연도를 옮기면 지도도 그 해 것으로. 없으면 가장 가까운 이전 지도를 흐리게 + `2015~21년 지도 없음 · 2013~14 지도 표시 중`.
- [연도별 자료 보기] → **이름이 아니라 SiteId 로 묶어서** 전 연도 자료를 한 표로.

## 7. 그 밖의 맹점

| # | 무엇이 터지나 | 막는 법 |
|---|---|---|
| 1 ●●● | **이름으로 자료를 잇는 코드가 남아 있으면 이 설계가 무용지물이다.** 통계·비교가 `Site` 문자열로 group by 하면 2015 오산천3과 2025 오산천3이 계속 한 줄로 묶인다 | SiteId 도입(SITE_MASTER_PLAN §2 (가))과 **같은 시점에** 통계 쿼리를 SiteId 기준으로 바꾼다. 둘 중 하나만 하면 의미 없다 |
| 2 ●●● | **양쪽에서 지도를 고치면 서로 달라진다** — 이번 지시로 받아들인 위험이다 | 막지 않는다. 대신 지도 목록에 `출처`와 `수정일`을 보여주고, [내보내기]로 맞출 수 있게 한다. 필요해지면 그때 잠금을 넣는다 |
| 3 ●● | **조류·포유류를 지점 체계에 억지로 맞추면 틀린다.** 조류는 5구간, 포유류 2025는 17지점으로 서로 다르고 오산천1~13과 대응하지 않는다 | 구간 레코드를 따로 만들고 `Taxa` 로 격리. 좌표 판정에서도 제외하거나 반경을 크게 준다 |
| 4 ●● | **포유류 2024 `오산천_12`·`오산천_24`** 는 좌표가 권역 전체에 흩어져 지점명이 아니라 날짜·차수로 보인다 | 이름 이력에 넣지 말고 [확인필요]로 남긴다. 억지로 매칭하면 틀린 이력이 굳는다 |
| 5 ●● | **보정 없는 과거 지도에 마커를 찍으면 엉뚱한 위치** | `Calibration: null` 이면 마커를 그리지 않는다 |
| 6 ●● | **지도 파일이 크다.** 서식수변 22-23(7.2 MB), 수질 22-24(1)(6.1 MB), 저서동물 22-23(6.8 MB)·13-14(5.7 MB) — 합계 약 36 MB | 앱에 넣을 때 **긴 변 1600 px·PNG 최적화**. 원본은 `2_database\조사지점` 에 보관 |
| 7 ●● | **`site_names.json` 기간이 겹치거나 빈다** | 로드 시 검사. 겹침은 오류, 빈 구간은 경고. 자동으로 메우지 않는다 |
| 8 ● | **`Source:"시트"` 를 계산에 쓰면 틀린 이력이 섞인다.** 시트에는 DB에 없는 07~09년 어류 이름 등이 있다 | 계산·조회는 `DB확인` 만 |
| 9 ● | **파일명에 `(1)`,`(2)`,`png.png` 가 섞여 있다** | 앱에 넣을 때 `권역_분류군_기간_Variant.png` 로 정규화. `maps.json` 이 원본 파일명을 `OriginalFile` 로 기억 |
| 10 ● | **위성 지도 저작권** | 앱 내 열람 전용. 내보내기·인쇄 기능은 만들지 않는다 |
