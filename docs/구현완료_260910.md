## 3. 설계에서 바꾼 것 · 왜

### 3-1. 지도가 좌표 없이도 열린다
설계서에는 `위·경도가 둘 다 유효할 때만 [지도] 활성` 이라고 적었는데 **그대로 하면 안 됩니다.**
지도 관리로 들어가는 입구가 이 버튼뿐이라, 좌표를 넣기 전에는 **올해 지도를 받아도 넣을 방법이 없습니다.**
그래서 버튼은 항상 열리고, 좌표가 없으면 마커만 안 찍고 안내 문구를 띄웁니다.

### 3-2. 시드 지도의 DPI 함정
`곡교천_26_기준.png` 는 **DPI 가 82** 입니다. WPF 는 이미지 크기를 `픽셀 × 96 ÷ DPI` 로 계산하므로,
크기를 지정하지 않으면 521px 짜리가 610 으로 그려지고 **마커가 가로로 17% 어긋납니다.**
그래서 이미지와 캔버스 크기를 픽셀 값으로 직접 박았습니다(`ImageSize` 주석 참조).

### 3-3. [새 야장] 명령은 만들지 않았습니다
설계서 §4 에 있던 `SessionService.StartNew()` 는 뺐습니다. 이 앱에 "새 야장" 흐름이 원래 없고,
넣으려면 캡션 바에 버튼을 하나 더 달아야 해서 범위가 커집니다.
지금은 **앱을 켤 때** 고정값이 들어갑니다 — 조사자가 매일 앱을 켜므로 실제 현장 흐름은 이것으로 충분합니다.
여러 지점을 이어서 도는 흐름은 자료함 `[지점 복사]` 가 이미 조사개황을 유지합니다.

### 3-4. `sitepack` 배포·확정 잠금은 넣지 않았습니다
지시하신 대로 지도는 참고 자료로 다루고, 승인·잠금 없이 양쪽 앱에서 자유롭게 고치게 했습니다.
남긴 안전장치는 둘뿐이고 둘 다 **정확성** 문제입니다.
1. 다른 해상도로 교체하면 보정을 지우고 재보정을 요구합니다 — 안 그러면 마커가 엉뚱한 데 찍힙니다
2. 보정 두 점이 너무 가까우면 경고합니다(막지는 않습니다)

## A. 행 삭제 (요청: "선택 후 삭제 버튼 + 마우스 우클릭 삭제")

- 빠른추가 바에 **`[행 삭제]`** 버튼, 그리드 **우클릭 → `이 행 삭제`** — 같은 명령입니다.
- **확인창이 반드시 뜹니다.** 문구는 `「3번 행 · 밀어」 을(를) 지울까요?` — 번호를 함께 넣은 이유는,
  이 기능의 본래 용도가 *같은 종이 두 줄 생겼을 때* 라서 종명만으로는 어느 줄인지 구분이 안 되기 때문입니다.
  기본 버튼은 **[취소]** 입니다(이 앱은 Enter 로 행을 추가하는 흐름이라 Enter 한 번에 지워지면 안 됩니다).
- 어느 행이 지워지는지 잡는 규칙
  - 셀·**2단 행(조류·포유류·양서파충류의 아랫줄)** 어디를 눌러도 그 행을 겨눕니다.
  - **머리글·빈 여백을 누르면 버튼이 꺼집니다.** (옛 행이 남아 엉뚱한 줄이 지워지는 걸 막습니다.)
  - **키보드로 셀을 옮기면(Tab·방향키) 버튼이 꺼집니다.** 지울 행을 다시 눌러 고르면 됩니다.
  - 맨 아래 **새 행(인서트 행)** 은 대상이 아닙니다.
  - 세션을 새로 불러오면 대상이 초기화됩니다.
- 관찰형 그리드의 **열 정렬을 잠갔습니다**(어류·저서동물과 같은 규칙). 확인창의 `n번 행` 이 화면 순서와 어긋나지 않게 하기 위함입니다.

## C. "지도 이미지를 찾지 못한다" — 원인과 조치

**원인**: 시드로 넣은 지도가 **곡교천 권역 3장뿐**인데, 지도 고르기가 *그 지점에 딱 맞는 지도* 만 찾고 있었습니다.
그래서 오산천 지점(가장 최근 세션)이나 생태현황에서는 목록이 **0장** → "등록된 지도가 없습니다" 로 보였습니다.

**조치**
1. 3단 폴백 — ① 그 지점 → ② 대분류만 맞는 것 → ③ 전부. **빈 화면은 이제 나오지 않습니다.**
2. 대신 딱 맞는 지도가 아니면 **띠로 분명히 알립니다** — `오산천6에 등록된 지도가 없습니다. 아래는 다른 권역 지도라 위치가 표시되지 않습니다.`
   이때 **마커도 찍지 않습니다**(문구와 화면이 어긋나지 않게).
3. 지도 관리 창 아래에 **지도 폴더 경로**를 항상 띄웠습니다. 메일로 받은 새 지도를 여기에 넣으면 됩니다.
4. **`[이 지점에 적용]`** 버튼 신설 — 새로 [추가]한 지도에 *지금 야장의 대분류·지점* 을 붙입니다.
   이걸 눌러야 그 지점 지도가 됩니다. 기본으로 열리게 하려면 **[최신으로]** 도 같이 누르세요(순서: 적용 → 최신으로).

**파일은 정상적으로 열렸고 WPF 디코딩에서 터진 것**입니다.

`BitmapCreateOptions.IgnoreImageCache` 는 `UriSource` 로 읽을 때만 쓸 수 있습니다. 이 앱은 파일을 잠그지 않으려고
`StreamSource` 로 읽는데, 스트림에는 URI 가 없어 WPF 가 URI 로 캐시 키를 만들려다 null 키로 던집니다.

## 게시 스크립트 — .cmd 에 한글을 넣지 말 것

첫 실행에서 `'SM_Surveyor_App.csproj'은(는) ... 아닙니다` 라는 이상한 오류가 났습니다.
`SD` 두 글자가 잘려 나간 것이 단서였습니다.

**원인** — cmd.exe 는 배치 파일을 실행하면서 바이트 단위로 읽는데, 파일이 UTF-8 인데 BOM 이 없으면
멀티바이트 한글에서 **읽는 위치가 어긋나** 다음 줄이 잘린 채로 실행됩니다.
기존 `build.cmd` 가 멀쩡했던 이유는 그 파일에 **BOM 이 있어서**였습니다(`EF BB BF` 확인).

**조치** — 한글이 필요한 일은 전부 PowerShell 로 옮겼습니다.

| 파일 | 인코딩 | 역할 |
|---|---|---|
| `tools/publish.ps1` | UTF-8 **with BOM** | 실제 작업 전부(감사 → 게시 → 확인 → 압축) |
| `tools/publish_test.cmd` | **ASCII 전용** | `publish.ps1 -Test` 를 부르는 한 줄 |
| `tools/publish_release.cmd` | **ASCII 전용** | `publish.ps1` 을 부르는 한 줄 |

PowerShell 은 UTF-8 BOM 파일을 정확히 읽고 한글 경로·파일명을 그대로 다룹니다.
`.ps1` 은 반드시 **BOM 을 붙여** 저장해야 합니다 — BOM 이 없으면 Windows PowerShell 5.1 이 CP949 로 읽어 깨집니다.

**검증** — Linux 에 PowerShell 7 을 올려 파서로 구문을 확인하고, `dotnet`·`python`·`explorer` 를 스텁으로
바꿔 전 구간을 실제로 돌려 봤습니다. 테스트본(예시 자료 3건 포함)과 실배포본(예시 자료 없음) 양쪽,
그리고 "실배포본에 예시 자료가 섞였을 때 중단되는지" 까지 확인했습니다. zip 안 한글 파일명도 정상입니다.
