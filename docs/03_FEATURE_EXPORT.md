## 0. 배경 (왜 두 종류인가)

기존 엑셀은 보고서용 계산식을 모두 품고 있어 입력이 복잡하고, 사업별 파일이 연 30개 넘게 쌓인다.
→ **입력·계산은 조사자 앱이 담당**하고, 엑셀은 두 목적으로만 쓴다.

| 종류 | 목적 | 우선순위 |
|---|---|---|
| **① 보고서·기록용** | 조사자가 보고서 작성 시 사용. 계산 과정·결과·등급 수록 | **주력** |
| **② 일괄입력용** | 현행 관리자 Import로 취합 | 레거시(병행 유지, 삭제 금지) |

**분류군별 개별 파일**로 내보낸다(사용자 결정).

## 2. 보고서·기록용 양식 (모든 분류군 공통 구조)

### 시트1 `조사개황`
`항목 | 값` 2열. 조사개황(공통) + 해당 분류군 고유 정보(채집방법·서식처·측정조건 등).

### 시트2 `출현종`
**지점명을 맨 왼쪽 컬럼**으로 둔 1행1종 표. 헤더에 필터. 여러 조사를 이어붙여 한 표에서 관리할 수 있게 한다.
`지점명 | 목 | 과 | 국명 | 학명 | 개체수 | 보호종`
- 관측된 종(**개체수 > 0**)만 기록. 0·미입력은 제외.
- 관찰형(조류·포유류·양서파충류)은 그 분류군의 컬럼 구성에 맞춘다(흔적·도래유형 등 포함).

### 시트3 `건강성평가(<지수명>)`
**지점명 포함, 1조사 = 1행**의 관리 테이블. 계산 **과정(산출값) → 배점 → 결과 → 등급**을 한 행에 모두 수록.
공통 앞부분: `지점명 | 연도차수 | 하천명 | 조사일`

| 분류군 | 건강성평가 시트 내용 |
|---|---|
| **어류** | 하천차수·총출현종수·총개체수·우점종 / **M1~M8 각각 (산출값, 배점)** / FAI총점 / 등급 — **구현 완료, 이 형식을 기준으로 삼는다** |
| **저서동물** | 총출현종수·총개체수·우점종 / **DI·H'·R1·J'** / BMI 계산요소(**Σ(s·g·h), Σ(g·h)**) / BMI점수 / 등급 |
| **수질** | 측정항목별 **(측정값, 등급)** 8종(PH·BOD·COD·TOC·SS·DO·TP·대장균군) + 생태독성 + 추가항목 14종 값 |
| **서식수변** | **평가항목1~10 각 점수** / 합계 / **평가점수(합÷2)** / 등급 |
| **조류·포유류·양서파충류** | 건강성평가 지수 없음 → 시트명 `출현종요약`: 총종수·총개체수·법정보호종 목록·흔적유형별 합계 |

> 계산은 반드시 `Ecology\` 의 기존 계산기를 사용한다. 내보내기에서 계산식을 다시 구현하지 말 것.
> 어류는 `EcologyCalculator.CalculateFaiDetail()` 처럼 **중간 산출값을 노출하는 메서드**가 필요하다.
> 저서·수질·서식수변도 동일하게 상세 결과 클래스(`BmiResult` 등)를 추가한다.

## 3. 일괄입력용 양식 (레거시)

`90_TECH_NOTES.md` §4의 셀 매핑을 **그대로** 따른다. 임의로 바꾸지 말 것.

- 완료: 어류(`FishExcelExporter`), 저서동물(`BenthosExcelExporter`)
- 남음: 수질·서식및수변(전치), 조류·포유류·양서파충류(일반 1행1기록)
- 자동계산 필드는 **비운다**(관리자가 재계산)
- 파일명에 `방류하천`/`생태현황` 키워드 필수
- 수질 확장항목은 **C열에 라벨 텍스트**를 넣어야 관리자가 찾는다

## 4. 화면 버튼 구성 (7개 화면 공통)

하단 상태바 우측: `[빈 행 정리] [임시 저장] [일괄입력용] [보고서 엑셀]`
- **보고서 엑셀** = 주력(②번 양식)
- **일괄입력용** = 레거시(①번 양식). 툴팁으로 용도를 구분해 표시.
- 두 버튼 모두 **유효 개체가 1건 이상이면 활성화**. 이상치 경고는 활성화를 막지 않는다.
