# 별도 작업 — 계산식 일치 검증 (관리자 `GB.cs` ↔ 조사자 `Ecology\`)

> 본 순서(01~06) 밖의 독립 작업. **DB를 건드리지 않는 순수 코드 대조라 위험이 없다.**
> 필독: `90_TECH_NOTES.md` §5(생태 계산식)
> 이 결과는 `05_REFACTORING.md` §2(`SDSM_Core` 추출)의 **선행 자료**다.

---

## 1. 왜 하는가

FAI·BMI·다양도지수·수질등급·HRI 계산식이 **두 곳에 따로 구현**되어 있다.

| | 위치 |
|---|---|
| 관리자 | `SDSM\SDSM_App\GB.cs` |
| 조사자 | `SDSM_Surveyor\SDSM_Surveyor_App\Ecology\` |

관리자는 일괄입력 시 엑셀의 지수 값을 무시하고 **원자료로 재계산**한다.
→ 두 구현이 조금이라도 다르면 **조사자 화면의 등급과 관리자 DB의 등급이 어긋난다.**
반올림 방식·결측 처리·정수 나눗셈 한 줄 차이로 충분히 발생한다.

> 조사자 앱을 실제 배포하기 전에 반드시 확인해야 하는 항목이다.

---

## 2. 방법

**관리자 앱을 실행하지 않는다. DB에도 쓰지 않는다.** 두 구현을 직접 호출해 결과만 비교한다.

1. 임시 콘솔 하네스를 만든다(저장소 밖 스크래치패드).
   - `SDSM_App`(또는 `GB.cs`가 포함된 어셈블리)과 `SDSM_Surveyor_App`을 **둘 다 참조**
   - `GB.cs`가 `SDSM_App` 내부라 참조가 어려우면 **`GB.cs`를 하네스에 복사**해 쓴다(원본 수정 금지).
2. 동일한 입력을 양쪽에 넣고 결과를 비교한다.
3. 불일치는 **입력값·양쪽 결과·차이**를 표로 출력한다.

## 4. 입력 케이스 (경계값 중심)

단순 정상값만 넣으면 차이가 안 드러난다. **경계와 예외를 반드시 포함할 것.**

1. **정상 케이스** — 어류 10종 정도, 저서 15종 정도의 평범한 조사자료
2. **등급 경계** — FAI 총점이 정확히 `80 / 60 / 40 / 20`, BMI가 `80 / 65 / 50 / 35`가 되는 조합
3. **M1~M8 구간 경계** — 하천차수 1~7 각각에 대해 각 메트릭의 구간 경계값
4. **비율 경계** — 내성종·잡식종 `30% / 70%`, 충식종 `20% / 45%`
5. **비정상종 비율** — 0, 0 초과 1 이하, 1 초과 (⚠ 관리자는 **정수 나눗셈**이라 대부분 0이 된다)
6. **결측·0 구분** — 개체수가 `null`인 행, `0`인 행이 섞인 자료
7. **조사불가** — `접근불가`·`건천화`·`준설`·`공사중` (등급이 `-`가 되어야 함)
8. **총개체수 0 / 종수 0** — 0으로 나누기 방어 확인
9. **동점 처리** — 우점종·순위점수에서 개체수가 같은 종이 여러 개
10. **수질 등급 경계** — 각 항목의 등급 구분값 정확히
11. **HRI** — 평가항목 합이 홀수(÷2에서 소수 발생), 일부 항목 미입력

## 6. 불일치 발견 시 처리 원칙

**임의로 한쪽을 고치지 말 것.** 아래 순서로 판단한다.

1. **지침이 정답이면** 지침에 맞는 쪽을 채택하고, 틀린 쪽 수정을 `05_REFACTORING.md`에 과제로 기록한다.
2. **관리자가 관행상 맞으면**(기존 수년치 데이터가 그 계산으로 쌓여 있으면) **관리자 동작을 보존**한다.
   과거 데이터와의 연속성이 깨지면 연도별 비교가 무의미해진다.
   - 단, **결함은 관행이 아니다.** 기존 동작이 명백한 버그면 지침대로 고친다(아래 M8 사례).
3. 어느 쪽이든 **결정과 근거를 `90_TECH_NOTES.md` §5에 기록**한다. 나중에 "왜 이렇게 했지"가 반드시 생긴다.

> ⚠ 이 판단은 생태 전문가(사용자)의 확인이 필요할 수 있다. **불일치가 나오면 임의 결정하지 말고 보고할 것.**

### 이미 결정된 건 — M8 비정상종 비율 (2026-08-20)

대조를 시작하기 전에 **이 항목은 이미 결론이 났다.** 대조 대상이 아니라 **수정 대상**이다.

- 현행: `(abnormalCount / totalIndiv) * 100` → 둘 다 `int`라 **정수 나눗셈**, 사실상 항상 0%
- **수정**: `(double)abnormalCount / totalIndiv * 100.0` (총개체수 0이면 0)
- **관리자 `GB.cs`와 조사자 `EcologyCalculator` 양쪽을 함께 고친다.**
- 근거·예시는 `90_TECH_NOTES.md` §5 참조.

> 이 수정을 **먼저 적용한 뒤** 나머지 항목을 대조하라. 안 그러면 M8이 계속 불일치로 잡힌다.
> 과거 데이터 재산출은 별도 과제다 → `..\..\SDSM\docs\ADMIN_TASKS.md` §6

## 8. 완료 기록 (2026-08-20)

**결과: 1,379건 대조 · 일치 1,367 · 불일치 12.**
수질 등급 8종(67건)과 저서 지수(DI·H'·R1·J'·순위점수)는 **완전 일치**.
HRI는 관리자 **일괄입력(DB 저장) 경로와 32건 전부 일치**한다.

| 남은 차이 | 실무 영향 | 처리 |
|---|---|---|
| 어류 **0종 자료** → 관리자 37.5·D / 조사자 null | **있음** | ⏸ 사용자 결정 대기 |
| BMI 음수 등급 `Check` vs `E` | 없음(오탁치 s>4에서만) | 통합 시 `Check` 채택 |
| HRI 빈 자료·`"접근 불가"` | 없음(관리자 편집화면 한정) | 관리자 편집화면 결함으로 기록 |

**함께 발견(양쪽 동일해서 "불일치"는 아니지만 결함)**
- **M8 정수 나눗셈** — 비정상 199/200(99.5%)도 0%로 계산되어 M8이 사실상 항상 만점.
  → 사용자가 이미 수정 결정(`ADMIN_TASKS.md` §6 · `90_TECH_NOTES.md` §5). **이 작업에서는 코드를 고치지 않았다.**
- **0으로 나누기** — 총개체수 0 + 비정상 개체수 > 0 이면 **양쪽 모두 `DivideByZeroException`**.
  M8 수정 시 `총개체수 > 0` 가드를 함께 넣으면 해소된다.

**방법**: 관리자 `GB.cs`의 계산 구간(저서 L397~597 / 어류 L599~813 / 수질 L815~913, 총 515줄)을
스크래치패드 하네스로 **그대로 복사**해 조사자 `Ecology\` 와 동일 입력으로 호출·비교했다.
HRI는 GB.cs가 아니라 두 ViewModel에 있어 워크시트/VM 의존부만 걷어내고 옮겼다(편집화면·일괄입력 둘 다).
관리자 저장소는 **읽기만** 했고 커밋 대상 변경이 없음을 확인했다.
