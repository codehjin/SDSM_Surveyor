### 하지 말 것

- ❌ **`..\SDSM\`(관리자 앱 저장소) 아래 파일을 한 줄도 고치지 않는다.** `SDSM_Core`·`SDSM_Models`·`SDSM_App` 모두.
  조사자 앱이 상대경로로 참조하므로 고치면 관리자 앱이 함께 바뀐다. 관리자 DB(`SDSMDB.sqlite`)도 쓰지 않는다.
  - 생태 계산식(FAI·BMI 등)은 그대로 둔다. 중복 종 문제는 **입력 단계에서** 막는다(B-1).
  - 관리자 코드표의 오타 `산강형`도 고치지 않는다(작업로그에만 남김).
- ❌ 개체밀도 환산을 넣지 않는다. 총 개체수 = 실측 개체수.
- ❌ 흐름상태 비율(%) 입력을 만들지 않는다. 양식대로 여울/흐름/소 **복수 선택**.
- ❌ 하상구성에서 암반·콘크리트를 빼지 않는다. **8칸 유지**.
- ❌ 어류 채집 **횟수** 칸을 만들지 않는다(양식에 없음).
- ❌ 빠른추가 바의 `RadComboBox`를 `RadAutoCompleteBox`로 바꾸지 않는다(`QuickAddBar.xaml:15-16` 주석 — 고르려면 두 번 눌러야 하게 된다).
- ❌ 결측(`null`)을 0으로 채우지 않는다. 합산·변환·내보내기 어디서든.
- ❌ 종명 정규화는 `Trim()`만. 대소문자·내부 공백을 바꾸지 않는다(CLAUDE.md §5).
- ❌ 일괄입력용 파일명 형식 `{대분류}_{지점}_{분류군}_DB_v1.xlsx`를 바꾸지 않는다. 관리자 Import가 파일명 키워드로 대분류를 판별한다(`ReportExporterBase.cs:91`).
- ❌ 기존 세션 JSON의 속성 이름·형식을 바꾸지 않는다. 바꿔야 하면 멈추고 구버전 호환 방안과 함께 제안한다.
- ❌ `%AppData%\SDSM_Surveyor\`(실제 조사 자료)를 옮기거나 지우는 방식으로 시험하지 않는다(90_TECH_NOTES §8).
- ❌ `BitmapCreateOptions.IgnoreImageCache`를 쓰지 않는다(`Helpers\ImageSize.cs` 주석).
- ❌ 새 NuGet 패키지를 넣지 않는다. 필요하면 멈추고 제안한다(CLAUDE.md §0).
- ❌ 새 `.cmd`에 한글을 쓰지 않는다. 한글이 필요하면 `.ps1`(UTF-8 **BOM 있음**). `publish.ps1`을 고칠 때도 BOM을 유지한다.
- ❌ 커밋·푸시는 하지 않는다. 사용자가 Visual Studio에서 직접 커밋한다. 단계가 끝나면 보고 끝에 **커밋 메시지 안**만 적는다.

## 4. 1차 — 버그 (B-1 ~ B-8)

권장 순서: **B-7 0단계(왕복 시험)** → B-1 → B-4 → B-2 → B-3 → B-6 → B-8 → B-5 → B-7 나머지.
B-7 0단계를 먼저 하는 이유: 결과에 따라 사용자 결정이 필요할 수 있어서다. 기다리는 동안 다른 항목을 진행한다.

### B-1. 같은 종을 두 번 넣음 — 5개 분류군 모두 입력 시점에 처리

- **원문**: "같은 종을 2번 이상 입력하였을 때 총 종수는 유지하고 개체만 변경되어야 하는데 다른 종으로 인식"
- **목적**: 종조사표를 옮겨 적다가 같은 종을 또 넣는 실수를 막는다. **종이 들어가는 5개 분류군 모두 적용**한다(수질·서식수변은 종이 없어 해당 없음).
- **원인(어류·저서)**: SDSM_Core 계산이 행 단위다(`GroupBy` 없음) → 종수 과대, 저서 BMI는 오탁치·지표가중치가 이중 합산된다.
- **분류군별 처리**

  | 분류군 | 처리 | 이유 |
  |---|---|---|
  | 어류 · 저서동물 (종 입력형) | **합산** — 한 행으로 합친다 | 한 지점·한 회차에 종당 한 행이 양식 구조. 관리자 Import도 종명 중복을 오류로 막는다 |
  | 조류 · 포유류 · 양서파충류 (관찰형) | **행은 넣고 경고** — 합치지 않는다 | 한 행이 관찰 1건(좌표·흔적·서식유형이 행마다 다름). 위치가 다르면 같은 종 여러 행이 정상. 종수 집계는 이미 `Distinct()` |

- **공통 구현**
  - `SpeciesEntryViewModelBase`에 중복 처리 방식을 둔다(예: `protected virtual DuplicateMode DuplicateSpeciesMode` — 어류·저서 `Merge`, 관찰형 3종 `Warn`).
  - 같은 종 판정: 국명 `Trim()` 후 `StringComparison.Ordinal` (`SelectedSpecies?.SpeciesKo ?? SpeciesKo`, 관찰형은 행의 `SpeciesKo`). `AddFromCatalog`의 기존 판정과 같게.
- **합산(어류·저서)**
  - 개체수 합산 규칙(결측 보존): `null+null=null` · `null+x=x` · `x+null=x` · `x+y=x+y`. 형이 다르므로(int?/double?) 파생 클래스가 합산을 맡는다.
  - 비고(`Note`)가 둘 다 있으면 ` / `로 잇는다. 버리지 않는다.
  - 경로별
    1. `AddQuick` — 같은 종 행이 있으면 새 행 대신 그 행에 더한다. 칩: `{국명} {기존}+{새} → {합} (합산)`.
    2. `PasteRows` — 기존 행과의 중복, 같은 붙여넣기 안의 중복을 모두 합산. 끝나면 칩에 `붙여넣기 n행 · 같은 종 k건 합산`.
    3. 그리드 수동 입력 — 국명 편집이 **확정된 뒤** 다른 행과 국명이 같아지면 먼저 있던 행으로 합치고 편집한 행을 지운다. 지우기 전에 `EndGridEdit` 호출(기존 `DeleteRow`와 같은 순서 — 편집 중 행을 지우면 예외). 국명이 바뀔 때만 합치고, 개체수만 고친 경우는 그대로.
    4. `AddFromCatalog` — 지금처럼 "이미 있음"(개체수가 없으니 더할 것이 없음). 변경 없음.
  - **불러온 세션의 기존 중복**은 자동으로 바꾸지 않는다. `ValidateRows`에서 해당 행에 `같은 종이 n행 — 합쳐야 계산이 맞습니다` 경고만 띄운다.
- **경고(조류·포유류·양서파충류)**
  - 빠른추가·붙여넣기·그리드 수동 입력 모두 **행은 그대로 넣는다.** 막거나 확인창을 띄우지 않는다(빠른 입력 흐름 유지).
  - 넣는 순간 칩에 `{국명} · 이미 n행 있음 — 중복이면 [행 삭제]`를 보여 주고, 같은 종의 다른 행도 '방금 추가' 강조로 잠깐 표시한다.
  - 같은 국명 행에는 상시 표시(예: 국명 옆 작은 뱃지 `같은 종 n행` + 툴팁)를 단다. 행 모델에 **세션에 저장하지 않는**(`[JsonIgnore]` 등) 계산 속성으로 두고 `Recalculate`에서 갱신한다. 세션 JSON 형식은 바꾸지 않는다.
  - 붙여넣기는 끝난 뒤 한 번만 칩: `붙여넣기 n행 · 이미 있는 종 k건`.
  - `AddFromCatalog` — 지금처럼 "이미 있음"(행을 만들지 않음). 변경 없음.
  - 표시 색은 기존 경고 토큰을 쓴다(새 색 추가 시 design.md §3.7 대비 계약).

### B-2. 국명 입력 중 받침이 다음 글자로 넘어감

- **원문 예**: `방울하루살이` 입력 시 `바다살이민물담치` 때문에 `바ㅇ`으로 넘어감 / `강하루살이` 입력 시 `가는무늬하루살이` 때문에 `가ㅇ`.
- **위치**: 그리드 국명 편집기 `RadAutoCompleteBox`(§3-7). 빠른추가 콤보에서도 재현되는지 함께 본다.
- **추정 원인(확인할 것)**: 자동완성이 첫 후보로 글자를 채우거나 첫 후보를 선택해, IME 조합 중인 글자가 확정된다.
- **조치**
  1. 위 두 예로 **먼저 재현**하고 작업로그에 재현 조건을 적는다.
  2. 자동완성이 텍스트를 채우지 않고 **제안만** 하도록 설정한다(`AutoCompleteMode` 등 — 속성 이름·기본값은 90_TECH_NOTES §0 절차로 어셈블리 메타데이터에서 확인. 추측 금지).
  3. 그래도 재현되면 IME 조합이 진행 중일 때는 필터·선택 갱신을 미룬다.
- **완료 조건**: 두 예가 그대로 입력되고, 목록에서 고르기는 여전히 한 번 클릭이다.

### B-3. 빠른추가에 종명을 쳐도 보기가 안 나옴

- **원인**: 콤보가 `OpenDropDownOnFocus`로만 열린다. 검색어가 바뀔 때마다 `FilterQuick`이 `FilteredQuick`을 **새 List로 교체**한다 → ItemsSource가 바뀌며 드롭다운이 닫히거나 열리지 않는다.
- **조치**: 검색어가 비어 있지 않게 바뀌면 드롭다운을 연다. 목록은 컬렉션 하나를 유지하고 내용만 갱신하는 방식을 우선 검토한다. **콤보 종류는 유지.**
- **완료 조건**: 초성(`ㅂㅇㅎ`)·완성형(`방울`) 입력 즉시 후보가 보이고, 키보드만으로 `검색 → ↓/Enter → 개체수 → Enter → 검색창 복귀` 흐름이 지금처럼 된다.

### B-4. 그리드 국명에 목록 밖 종을 치면 저장되지 않음 (조사 중 발견)

- **원인**: 편집기가 `SelectedItem`만 바인딩한다. 목록에 없는 국명은 `SelectedItem=null`이 되고 친 글자는 버려진다.
- **조치**: 편집기의 검색 텍스트도 행의 `SpeciesKo`에 바인딩한다(속성 이름은 메타데이터로 확인). 목록에 있으면 `OnRowPropertyChanged`가 공식 종목록과 매칭해 `SelectedSpecies`를 잇고, 없으면 국명을 그대로 저장하고 기존 미등재 경고 경로를 탄다.
- 관찰형 3종 편집기도 같은 문제인지 확인하고, 같으면 같은 방식으로 고친다.
- **완료 조건**: 목록 밖 국명이 저장·재열기 후에도 남고 경고가 보인다. B-1 합산 키에도 이 국명이 쓰인다.

### B-5. 닫을 때 저장 확인이 없음

- **원문**: "닫기 버튼을 누를 시 별도의 확인 없이 종료… '현재 입력 사항을 저장하시겠습니까?' 같은 확인이 있으면 좋을 듯"
- **조치 — 스냅샷 비교 방식(권장)**
  - `SessionService`가 "마지막으로 저장하거나 불러온 시점"의 스냅샷을 갖는다: 7개 분류군 + 조사개황을 세션 JSON으로 직렬화한 문자열(저장 시각처럼 매번 바뀌는 값은 뺀다).
  - `HasUnsavedChanges()` = 지금 직렬화한 값 ≠ 스냅샷.
  - 스냅샷 갱신 시점: 앱 시작 직후(압정 주입·예시 자료 시드 이후) · `SaveCurrentAsync` 성공 · `LoadAsync` · `CopyToSite` · `CopyFromPreviousAsync` · [새 지점](C-2).
  - 속성마다 dirty 플래그를 다는 방식은 화면 상태(접힘·검색어·칩)와 섞여 오판하기 쉽다. 스냅샷은 저장되는 내용만 본다.
- **창 닫기**: `Closing`에서 변경이 있으면 `현재 입력 사항을 저장할까요?` [예 / 아니요 / 취소], 기본 버튼 예.
  - 예 → `e.Cancel = true` → `SaveCurrentAsync` → 성공하면 다시 닫는다(재진입 플래그) / 실패하면 사유를 알리고 창을 유지.
  - 아니요 → 닫는다. 취소 → `e.Cancel = true`.
- 저장에 필요한 값(연도차수·지점 등)이 비어 저장할 수 없으면, 무엇이 필요한지 알리고 닫기를 취소한다. `SaveCurrentAsync`가 빈 값에서 어떻게 동작하는지 먼저 확인한다.
- **같은 확인을 쓰는 곳**: 지금 화면을 덮어쓰는 자료함 동작 — [불러오기] · [지점 복사] · [차수 복제].
- **완료 조건**: 바꾼 것이 없으면 묻지 않는다. 세션을 불러온 직후 닫으면 묻지 않는다.

### B-6. 하상구성 — 정수만, 저서에도 합계 경고

- **근거**: 최종본 실제 제출 자료에 합계 90%(저서 6건)·200%(어류 20건). 관리자 모델이 정수(`int?`)라 소수는 Import 오류.

  - 불러온 세션의 정수가 아닌 값은 지우지 않고 경고로 표시한다.

- 숫자 항목은 **숫자로** 쓴다(`SetValue(double)`). 문자열 `"3"`으로 쓰지 않는다. 선택값·다중값은 §3-5 규칙.

| 하천 | St.번호 상태 | 정렬 |
|---|---|---|
| 곡교천(13) | St.1~13 빠짐·중복 없음 | **St.번호 순** |
| 오산천(20) | 결측 1(오산천10), 중복 7쌍(예: St.4 = 오산천4·오산천5) | **지점명 숫자 순** |
| 원천리천(10) | 전부 없음 | **지점명 숫자 순** |

- **규칙**: 하천(`River`, 가나다) → 그 하천의 St.번호가 **빠짐·중복 없이 모두 있으면** St.번호 숫자 순, 아니면 **지점명 자연 정렬**(숫자를 수로 비교: `오산천9` < `오산천10`, `오산천3` < `오산천3_1` < `오산천3_2` < `오산천4`).
  하천마다 규칙을 데이터로 판정한다(하천 이름을 코드에 박지 않는다). 나중에 번호가 채워지면 저절로 St.번호 순이 된다.
- 결과(2026-10-15 자료 기준, 이대로 나오는지 확인):
  - 곡교천: St.1 곡교천1 … St.4 곡교천4 · St.5~6 회룡천1~2 · St.7~9 천안천1~3 · St.10 공수리1 · St.11 성성공원 · St.12~13 북수리1~2
  - 오산천: 1 · 2 · 3 · 3_1 · 3_2 · 4 · 4_1 … 4_5 · 5 · 6 · 7 · 8 · 9 · 10 · 11 · 12 · 13 (좌표상 상류→하류와 거의 같음)
  - 원천리천: 0 · 1 · … · 9 (상류→하류와 일치)
- **St.번호 표시**도 같은 판정을 따른다: 번호를 믿을 수 있는 하천(곡교천)만 `곡교천1 (St.1)`처럼 보이고, 나머지는 지점명만 보인다. `SurveySite.Display`는 공유 모델이라 고치지 않고 조사자 앱 쪽 표시 문자열로 만든다.
- **St.번호로 지점을 칠 때의 오류도 고친다.** 공유 코드 `SiteResolver.Resolve`(`SDSM_Core\Data\SiteResolver.cs:44-61`)는 대분류 전체에서 **처음 맞는 지점**을 고른다. 그래서 `St.4`를 치면 하천과 상관없이 늘 `곡교천4`가 되고, 오산천의 중복 번호도 한쪽으로만 간다.
  - `SiteResolver`는 고치지 않는다. 조사자 앱 `SiteListProvider.Resolve`에서 감싼다: 입력이 St.번호 형태면 후보(같은 St.번호·지도 번호인 지점)를 모두 모으고, **후보가 둘 이상이면 자동으로 고르지 않고** 지점 콤보에 그 후보만 보여 준다. 후보가 하나일 때만 자동 선택.
  - 지점명 정확 일치(①)는 지금처럼 바로 고른다.
- `sites.json`의 St.번호 값은 고치지 않는다. 정렬·표시·해석을 조사자 앱에서 처리한다.

### C-8. 여러 지점 일괄 출력

- 자료함에서 세션을 여러 개 고르고 [보고서 일괄] / [일괄입력용 일괄].
- **일괄입력용**: 고른 폴더에 세션 × 분류군 파일을 만든다. 파일명 형식은 유지하고, 같은 이름이 생기면 `연도차수` 하위 폴더로 나눈다.
- **보고서(한 파일)**: 배치(예: 분류군별 통합문서에 지점별 시트 / 한 시트에 지점 블록)는 **먼저 안을 보고하고 사용자가 고른 뒤** 만든다.
- 구현: 세션을 화면 VM에 차례로 불러와 `Write(vm, path)`로 쓴다. `LoadAsync`가 싱글턴 VM을 덮어쓰므로 시작 전에 B-5 확인을 거치고, 끝나면 보던 화면을 그대로 되돌린다.

### C-9. 자료함 [내보내기]·[가져오기]

- [내보내기]: 고른 세션을 `.zip`으로(세션 JSON + 색인 항목). [가져오기]: zip을 검사한 뒤 세션을 추가한다.
- 같은 세션 키(대분류·연도차수·지점)가 있으면 덮어쓸지 묻는다. 기본은 건너뜀.
- 깨진 zip·JSON은 그 건만 건너뛰고 결과를 요약한다. `System.IO.Compression`(기본 라이브러리)을 쓴다.

## 7. 기술 메모

- **Telerik API는 추측하지 않는다.** 90_TECH_NOTES §0 절차로 어셈블리 메타데이터에서 확인한다.
  예: `GridViewCurrentCellChangedEventArgs`는 없다(실제 `GridViewCurrentCellInfoChangedEventArgs`). `ParentOfType<T>()`는 `Telerik.Windows.Controls.ParentOfTypeExtensions`에 있다.
- 그리드에서 행을 지우거나 합치기 전에 `EndGridEdit`를 호출한다. 편집 중인 행을 지우면 예외가 난다.
- `new XlsxFormatProvider().Export(wb, stream, null)` — 3번째 인자 필수. 셀 인덱스는 0-based(이 문서 표의 행 번호는 엑셀 1-based).
- `RadGridView`는 열이 넘쳐도 가로 스크롤을 만들지 않고 열을 뭉갠다(90_TECH_NOTES §2).
- 7개 EntryViewModel과 `SurveyMeta`는 싱글턴이다. `SessionService`는 7개 VM을 `IServiceProvider`로 늦게 가져온다(생성자 주입은 순환 의존). 새 서비스도 같은 규칙.
- 프로그램이 여러 칸을 한꺼번에 넣는 구간은 `BeginBulkApply/EndBulkApply`(카운터)로 감싼다.
- 색·치수는 `Colors.xaml`·`Styles.xaml` 토큰만 쓴다(XAML 색 리터럴 금지, design.md §1).
- 안내 문구는 현행 톤(`~합니다`, `~할까요?`)을 따른다.
- 빌드 게이트: `tools\build.cmd`(xaml_audit + contrast_audit + dotnet build), 경고 0 유지. 앱이 실행 중이면 빌드가 실패한다.
- 배포 검사: `tools\publish.ps1`(테스트판 `-Test`). 내장본 6개 확인을 추가한다.
